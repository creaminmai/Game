# 햇살병원 아트·UI 개선 검토

작업 기준: 2026-11-04 사용자가 제공한 따뜻한 병원 콘셉트와, 같은 대화에서 추가한 크림색 상단 바·청록 버튼·환자 단계 패널의 게임 화면. 목표 원본은 대화 첨부 이미지이며 임의의 다른 스타일이나 배경 그림으로 대체하지 않는다.

## 목표와 실제 장면의 차이

| 항목 | 작업 전 엔진 화면 | 목표와 적용 방향 |
| --- | --- | --- |
| 공간 | 탁한 회녹색 바닥·벽, 검은 타일 격자 | 크림·연한 민트의 연속 바닥, 얕고 낮은 대비의 경계 |
| 접수대 | 깊고 어긋난 세로 홈, 얼룩진 상판 | 둥근 크림 상판, 실제 외곽을 따르는 얕은 목재 디테일 |
| 소파 | 거친 색 무늬, 밝고 어두운 파이핑 | 코랄색의 두툼하고 매끈한 쿠션, 조용한 표면 |
| 장비 | 얼굴처럼 불룩한 CT 외장, 둔탁한 반사 | 넓은 전면 패널과 매끄러운 보어, 별도 회전부·헤드의 치료기 |
| 캐릭터 | 거친 접촉 음영, 돌출된 눈, 촘촘한 머리 선 | 얼굴 표면을 따르는 눈·볼, 약 2.7등신, 민지의 갈색 단발·청록복 |
| 조명 | 전체가 비슷한 밝기, 넓은 면에 삼각형 음영 | 창가 방향 주광·중립 환경광·환경 반사를 분리하고 그림자 투영 수정 |
| UI | 짙은 단색 사각 버튼, 넓은 가로 환자 카드 | 크림색 둥근 프레임, 청록 행동 버튼, 오른쪽 진료 단계와 실제 캐릭터 초상화 |

소품 수를 늘리는 작업이 아니다. 접수대·대기 좌석·창문·식물·민지·환자 1명·CT를 같은 위치와 카메라로 먼저 비교한다. 병원 전체와 별관에는 같은 재질·장비 제작 규칙을 사용한다. 기존 외관 모델은 이번 대표 장면과 같은 수준으로 새로 제작한 것이 아니다.

## 파일과 재현

- [전후 비교 화면](art-review.html): 동일 카메라의 대표 장면·접수대 확대, UI 화면과 실제 엔진 영상.
- `art/source/*.blend`: 편집 가능한 원본. 정적 병원의 `editable parts` 컬렉션에는 가구별 파트를 보존한다. 이를 편집할 때 컬렉션의 모니터/렌더 표시를 켜고, 합쳐진 내보내기 메시를 숨긴다.
- `godot/assets/models/*.glb`: 실제 게임에서 사용하는 메시·PBR 재질·패킹된 텍스처. 캐릭터는 머리·팔·다리 피벗과 앉은 다리를 유지한다.
- `tools/art/build_assets.py`, `build_characters.py`, `export_models.py`: 재생성·예산·출입구 검사.
- `godot/assets/daylight.tres`, `godot/assets/window_reflection.gdshader`, `godot/scripts/world.gd`: 실제 엔진 환경, 반사, 주광·보조광·그림자 설정.
- `tools/art/build_ui.py`, `godot/assets/ui/`, `godot/scripts/ui_skin.gd`: 원본 SVG 프레임·아이콘과 엔진에서 촬영한 초상화.

## 재질·색 관리

장비의 주 외장 거칠기 0.29(보조 아이보리 0.42), 목재 0.48, 코랄 직물 0.76, 바닥 0.38, 피부 0.62, 머리카락 0.48을 사용한다. 비금속 외장에 금속성을 주지 않는다. 금속 부품은 별도 재질이다. 패턴은 기본색만 약하게 변화시키며 소파·피부에 노이즈 범프를 넣지 않는다.

색상 상수는 sRGB에서 Blender의 선형 기본색으로 변환한다. 목재·직물 기본색 PNG는 sRGB, AO는 Non-Color 데이터이며 UV1을 사용한다. Godot 가져오기 후처리에서 `ao_on_uv2`를 명시한다. 정적 AO는 선형 0.84~1, 캐릭터 정점 음영은 0.94~1로 제한한다. 조명 역할을 AO에 떠넘기지 않는다.

Blender 검토 카메라는 Standard/노출 0이며, 최종 판단은 Godot Compatibility의 실제 캡처로 한다. 엔진은 선형 톤매핑·노출 1을 유지하고 재질/광원/환경 반사를 따로 조정한다. AgX 렌더를 엔진 결과처럼 제출하지 않는다. SDFGI, SSAO, SSIL, 블룸, 화면 공간 반사에 최종 외형이 의존하지 않는다.

AO를 끈 진단에서도 남았던 큰 삼각형 음영은 그림자 투영을 바꾸어 확인했다. 카메라 원거리 범위와 2분할 주광 그림자, 깊이 정밀도와 바이어스를 명시한다. 그림자 맵은 네이티브 데스크톱 4096², 웹·모바일 2048²이며 웹·모바일에도 필터를 켠다. 조밀한 곡면을 보존하기 위해 작은 반복 부품을 UV 베이크 전에 줄이고, 큰 CT·쿠션을 한꺼번에 감량하지 않는다. 가져오기 단계의 추가 LOD 감량과 정밀도 축소를 끄고, 이미 제한한 게임 메시를 그대로 사용한다.

## UI와 운영 연결

자금·운영일·완료 수·환자 상태·진료 단계·행동 가능 여부는 실제 시뮬레이션에서 읽는다. 참고 이미지의 평판 수치나 시계를 가짜로 표시하지 않는다. 병원 전체 보기, 환자 목록, 지시가 필요한 환자, 증축, 병원 안/밖, 확대·축소, 정지·재생, 1/2배속을 조작할 수 있다. 미구현 연구·직원 채용·지도 메뉴는 활성 기능처럼 추가하지 않는다.

환자 운영·경로·점유·경제·저장 형식은 바꾸지 않는다. UI의 배속은 기존의 작은 시간 단위로 처리하는 시뮬레이션에 입력 시간을 전달한다. 영상은 실제 엔진과 실제 버튼 입력의 자동 시연이며, 영상의 6배속은 일반 UI의 1/2배속과 구분한다.

## 검증과 남은 차이

최종 검사 결과는 [검증 기록](validation.md)에 기록한다. Linux의 Mesa 소프트웨어 OpenGL과 Chromium WebGL로 확인한다. 화면 크기·터치 에뮬레이션은 실제 iPhone Safari의 GPU 성능·발열·메모리 검증을 대신하지 않는다.

목표 시안의 고급 캐릭터 조형, 손으로 다듬은 헤어 흐름, 실내 간접광과 반사 세부, 정원 밀도까지 동일하게 달성했다고 주장하지 않는다. 이번 단계는 실제 메시·재질·색·그림자 오류를 바로잡고 운영 가능한 게임 안의 시각 기준을 세우는 작업이다. 캐릭터는 명명된 부위 피벗 기반이며 최종 얼굴 리그와 표정 애니메이션은 남아 있다.

3D 공간은 HUD의 960×540 논리 좌표와 분리해 디스플레이 해상도에 맞추되 1280×720을 넘지 않는다. 환자 클릭과 드래그 좌표도 같은 비율로 변환한다. 창 크기 변경 후 패널 배치와 실제 렌더 크기를 검사한다.
