# 다음 제작 순서

최신 상세 규칙은 [제작 기준 메모](design-baseline.md)와 [보관된 첫 시즌·수익화 기획](../reference/README.md)을 따른다. 문서의 수치·상품 가격은 검증용 제안이며, 문서 보관이 해당 기능의 구현 완료를 뜻하지 않는다.

현재는 환자 4명 진료·별관 증축·다음 날·로컬 저장을 갖춘 3D 운영 프로토타입이다. 목표는 Mac/iPhone에서 쉽게 플레이하며 피드백할 수 있는 버전부터 만드는 것이다.

## 바로 다음 개발 단위

내부·환자·간호사는 별도 Blender/GLB 모델을 사용한다. 최신 작업에서 표면 노이즈·줄눈·그림자 오류를 정리하고 크림·청록 게임 UI를 적용했다. [최신 카메라 검토](stable-camera.html)로 안정적인 운영 시점과 병원 크기를 확인한다. 상태 안내·환자 카드·치료 자세는 이전 개선을 유지한다. 다음 시각 개선은 캐릭터 얼굴·자세 전환·업무 동작, 간접광과 재질 반사, 외관과 조경이다. 새 기능을 늘리기 전에 실제 Mac/iPhone 플레이로 화면 크기와 조작·성능을 확인한다.

가로 화면 기준, 접수·대기·CT 대표 장면, 환자의 앉은 자세, 드래그·줌, 접이식 환자 목록과 상황별 행동 버튼을 적용했다. 다음은 이 화면에서 첫 10분을 작은 완결 경험으로 만드는 일이다. 민지의 짧은 시작 안내, 현재 해야 할 일 하나, 완료 피드백, 첫 증축 목표, 하루 정산과 다음 날 목표를 연결한다. 실제 Mac/iPhone에서 카메라 이동과 환자 선택의 편의성도 확인한다. 수치와 난이도는 플레이 피드백 뒤 결정한다.

직원 자동 운영·지역 확장·연구소를 한꺼번에 붙이기보다 각각의 동작이 플레이로 확인되는 작은 단위로 진행한다. 수동 계획 퍼즐, 여러 날 치료 과정, 자유 건축 등은 별도 기능이며 아직 구현하지 않았다. 결제·광고·계정은 출시 방식과 사용자 요구에 따라 도입 여부를 정한다.

## 매 작업 완료 시 전달할 것

1. 변경한 기능을 보여 주는 실제 Godot 실행 MP4. 자동 시연인지, 배속인지 표시한다. 문서만 수정했다면 새 플레이 변경이 없다고 알리고 기존 영상을 안내한다.
2. 가능한 경우 같은 버전의 브라우저 체험 빌드. 공개 링크는 실제 응답과 게임 로딩을 확인한 뒤만 완료라고 말한다.
3. 변경 사항, 실행한 검사, 남은 제한, 해당 Git 커밋을 간단히 보고한다.
4. 검증한 소스를 main에 커밋·푸시하고 원격 SHA를 확인한다. 선택한 전달용 영상은 docs/media/에 보관하고 원본 AVI·캐시·임시 결과물은 제외한다.

Mac/iPhone 사용을 기준으로 웹 체험을 우선한다. 데스크톱 Chromium 테스트와 터치 에뮬레이션은 실제 Safari/iPhone 검증을 대신하지 않는다. 영상 24fps도 실기기 프레임 속도를 의미하지 않는다.
