# 챕터 4 · 기록이 바꾸는 하루

2026-11-08 시작 · 2026-11-10 KST 전달 검증. Godot 4.6.3, 가로 화면의 실제 3D 게임. 기존 900만 시작 / 일정 완료 200만 / 별관 600만 / 운영 교육 500만, 무료 접수 위임과 3초 준비 후 자동 계획 지시를 유지한다.

## 실제 구현

3장 완료 후 병원 밖의 연구소 예정지 또는 하단 ‘연구’에서 설립 내용을 확인한다. 1,800만을 명시적으로 구매하면 실제 Blender/GLB 연구소와 윤서진이 즉시 나타나고 최초 연구점수 6점을 한 번 받는다. 예정지는 본원 왼쪽에 있으며 본원·별관과 기존 환자 동선을 옮기지 않았다. ‘연구소 보기’는 사용자가 요청하는 상세 시점이고, 카메라 방향은 그대로다. 병원 복귀는 기존 운영 시점을 사용한다.

연구 화면에서 비용·효과·실제 날짜를 확인하고 별도로 연구를 시작한다. 슬롯은 하나이며 **완료 후 다음 날 적용을 기다리는 동안에도 사용 중**이다. 취소·환불·대기 타이머·일일 연구소 운영비·현금 결제는 없다. 설립 취소와 연구 시작 확인 취소는 거래를 만들지 않는다.

| 연구 | 한 번 사용하는 비용 | 실제 효과 |
| --- | --- | --- |
| CT 촬영 흐름 개선 I | 500만 + 연구점수 6점 | CT 단계 5초 → 4초. 이동·대기·치료 시간은 그대로 |
| 계획 협업 개선 I | 500만 + 연구점수 6점 | 실제 계획 검토 5초 → 4초. 자동 지시 전 준비 3초는 그대로 |

두 연구 중 어느 것을 먼저 골라도 된다. 수동·자동 명령 모두 같은 업무 시간을 사용한다. 업무가 시작할 때 환자의 `service_duration`을 확정하고 저장한다. 경과 시간을 덮어쓰거나 이미 진행 중인 업무를 완료시키지 않는다. 효과는 4초라는 값을 적용하며 반복 로드나 다음 날 입력으로 중첩되지 않는다. CT 자세도 이 저장된 시간을 사용한다.

## 운영일과 거래 기록

연구를 시작한 날은 진행일이 아니다. **5일차 시작 → 6일차 정상 마감에 연구 완료 → 7일차 환자 입장 전에 효과 적용**이다. UI도 해당 날짜를 표시한다. 현재 정상 마감은 네 방문 일정의 실제 귀가 완료와 그날 진료 수입이 확인된 상태다. 마감은 시뮬레이션에서 처리하며, 일지 열기·다시 열기·대화·저장 복원은 생산 이벤트가 아니다.

연구소가 있는 정상 마감마다 4점을 생산하고 200점까지만 더한다. 상한에 걸리면 실제 증가량(0~4점)을 기록한다. 이미 마감한 날에 연구소를 지으면 그날 점수는 소급 지급하지 않는다. 설립 당일 아직 마감 전이었다면 그날 정상 마감에서 생산한다. 최초 6점과 생산 4점, 연구 사용 6점은 각각 별도 거래다.

`HospitalResearchLab`은 설립·생산·연구 시작·완료·적용 영수증을 날짜와 종류/연구 ID로 보존한다. 복원 시 영수증을 재검증해 점수·프로젝트·완료 날짜·일일 지출과 일치하는지 확인한다. 부정합 저장은 전체 적용 전에 거절한다. 교육·무료 위임·기존 챕터를 초기화하지 않는다.

일일 장부 v3는 `lab_expense`, `research_expense`를 추가했다. 시작 자금 + 진료 수입 − 증축 − 교육 − 연구소 설립 − 연구 시작 = 현재 자금이다. 일지의 스크롤 영역에서 자금 지출과 점수 최초/생산/사용, 연구 완료·적용 예정/완료를 구분한다. 다음 날에는 일일 금액만 초기화하고 시설·연구·점수·위임 설정을 유지한다.

실제 정상 명령으로 진행한 기준 경로:

- 4일차 종료: 900 + 3,200 − 600 − 500 = **3,000만**.
- 5일차: 연구소 1,800만 + CT 연구 500만, 진료 수입 800만 → **1,500만**, 점수 4점.
- 6일차 마감: **2,300만**, 점수 8점, 연구 완료·적용 대기.
- 7일차 시작: 같은 잔액·점수, CT 4초 적용 및 4장 완료. 추가 챕터 보상 없음.

## 이야기와 성장 기록

윤서진은 진료 기록을 살피는 연구 담당이다. 기존 박 선생의 계획 검토, 박 원장 설정과 합치지 않았다. 소개는 윤서진·민지 두 줄, 첫 적용은 윤서진 한 줄이며 기존 공유 대사 채널에서만 표시한다. 자동으로 넘기지 않는다. 안내 끄기·대사 건너뛰기는 건설이나 연구 동의가 아니다. 안내를 다시 켜면 지난 장면을 쌓아 재생하지 않는다.

4장은 **연구소 설립 + 연구 한 개의 실제 효과 적용**으로 완료한다. 구매·진행·완료 대기에서는 미완료다. 성장 기록에서 이전 1~3장도 확인한다. 완료 소감은 병원 일지에 한 번 연결하고 완료 도장은 적용일 일지에 남긴다. 이후 자유 운영과 다음 날을 계속할 수 있다.

## 저장 호환과 중단·재개

기존 v2 게임 저장 안에 선택 필드 `research_lab` v1을 추가한다. 연구소·최초 지급·점수·마감 경계·프로젝트 날짜/진행/적용·영수증·대사/도장 표시 여부를 저장한다. 이전 장부 v1/v2와 연구 필드 없는 저장은 연구소 없음·0점으로 이전한다. 이전에 마감한 날짜의 점수를 추정하지 않는다. 이미 시작한 예전 CT·계획은 기존 5초를 복원한다. 사용자 저장을 지우지 않으며 검사는 별도 저장을 쓴다.

병원 밖·앱 비활성·사용자 정지는 기존 정책 그대로다. 복원은 일시정지로 시작하고 사용자가 재생한다. 외부 연구 화면을 다녀와도 사용자 정지를 해제하지 않는다. 현실 시간 경과로 연구나 진료를 완료시키지 않는다.

## 터치 스크롤 수정

Web 터치 검사에서 연구 카드의 `PanelContainer`와 일지 내용 `Control`이 기본 입력 차단 설정으로 드래그를 삼키는 문제를 발견했다. 두 내용 영역을 `MOUSE_FILTER_PASS`로 바꿔 상위 스크롤에 전달하고, 바깥 패널의 입력 차단과 구매 버튼 동작은 유지한다. 연구·일지를 실제 드래그해 스크롤 이동과 거래 불변을 확인하는 검사를 추가했다. Web 검사도 실제 렌더 프레임에 걸쳐 터치를 이동하고, 스크롤 밖 버튼 좌표를 누르지 않도록 확인한다.

Web 캡처에서 내장 한글 폰트가 지원하지 않는 `−`/`›`가 네모로 표시되어, 같은 의미의 지원 기호 `-`/`>`로 바꿨다. 자금·점수·목표 계산은 바꾸지 않았다.

## 검증과 남은 제한

핵심 운영 검사에서 양쪽 연구 순서, 잠김·비용·점수·슬롯 거절, 최초·일일 점수 중복/상한, 마감 후 설립, 5→6→7일 효과 적용, 기존 저장, 정상/변조 저장 원자성, 수동·자동 업무 시간을 확인한다. 새 CT 4초 모션은 실제 메시 충돌 검사와 60Hz 연속 자세·복원을 확인한다. 기존 운영·위임·일지·카메라와 네 해상도 UI도 회귀 검사한다.

별도 프로세스의 구매 직후·진행 중·마감 직전·적용 직전·적용 후·CT 중·다음 날 저장 재실행과 앱 알림 모사를 수행한다. Linux/Chromium 소프트웨어 렌더링 결과를 Android·iPhone 실기기 검사로 부르지 않는다. 물리 기기 FPS·발열·배터리, Safari/Xcode/스토어 출시 검증은 미완료다.

윤서진은 기존 캐릭터 기본형과 짧은 호흡·눈 깜박임 구조를 활용한다. 전용 연구 애니메이션·자유 이동·연구원 채용은 임시 범위 밖이다. 병원 밖 운영 정지 중에는 업무 애니메이션도 진행하지 않는다. 연구소 건설은 즉시 실제 건물로 바뀌며 타이머나 장기 공사 단계는 없다.

실제 CT 지속 시간은 단위 모션 검사와 1배속 영상에서 **4.000초**였다. 자세 검사는 기존 CT 승하차의 준비·눕기·검사·일어나기를 모두 관찰했고, 60Hz 최대 머리 이동 0.1162m, 검사 대상 머리·몸통·손의 장비 침범 없음으로 통과했다. 계획 검토는 실제 4초, 자동 지시 전 준비는 별도 3초로 확인했다. 연구소 건설 전 CT/계획 5초도 유지된다.

Chromium에서는 `76a84f2` Web의 마우스 첫 환자 접수·IndexedDB 저장과, 최종 `fb0c2aa` Web의 **844×350 터치 입력·스크롤**의 설립 취소/구매·연구 비용 차감·다음 날 적용·4초 CT 저장·실제 페이지 재로딩을 확인했다. 연구 테스트는 정상 운영으로 만든 세 체크포인트를 격리된 브라우저 저장에 넣어 검사했다. 마지막 집중 검사는 `--research-only`로 이미 확인한 첫 접수를 반복하지 않았고, 결과 JSON의 `first_admission_skipped`에 명시했다. 여러 날을 Web에서 연속 운영한 검사나 Safari 검사가 아니다. 검사 도구의 기존 장부 v2 기대값도 새 v3 항목으로 갱신했다.

작은 화면은 844×350, 844×390, 915×412, 1280×720에서 실제 Godot 렌더링/입력으로 검사했다. 작은 화면은 좌우 47·하단 21픽셀 안전 영역을 모사했으며 실제 휴대폰의 노치 측정은 아니다. 발견한 확인창 최소 폭/자동 줄바꿈과 성장 조건 줄바꿈을 조정해 화면 밖으로 밀리거나 다음 행과 겹치지 않도록 했다. 버튼 크기를 줄이지 않고 연구와 일지를 스크롤 구조로 배치했다.

**Linux Godot 4.6.3 Compatibility/OpenGL llvmpipe, 844×390, 정상 1배속, 자동 입력**이다. 녹화 24fps는 엔진을 고정 프레임으로 실행한 산출 형식이며 모바일 성능 수치가 아니다. 각 영상의 초기 설정 정지 프레임만 제거하고 게임 진행 프레임은 삭제·가속하지 않았다.

`research_fixture.gd`는 새 시뮬레이션부터 정상 접수·계획 명령, 실제 귀가·구매·다음 날로 상태를 준비한다. 준비는 녹화 전에 CPU에서 빠르게 수행한다. 자금·환자 상태·연구 진행·챕터 기록을 임의 대입해 달성하지 않는다. 중간 구간 전환은 영상의 알림과 JSON `checkpoint_switches`에 명시했다. 일부 준비 경로에서는 이전 챕터 일지를 열지 않았으므로 처음 여는 6일차 일지에 아직 확인하지 않은 3장 소감이 연결된다. 실제 저장에 이미 본 기록이 있으면 반복되지 않는다.

세 영상의 실행 소스는 `76a84f2`이다. 이후 터치 검사에서 발견한 연구 카드·일지의 입력 전달을 수정해 최종 빌드를 갱신했다. 두 내용 영역의 입력 필터와 읽기 전용 검사 좌표만 바뀌었으며 영상의 모델·카메라·연구 일정·정산·모션은 동일하다. 최종 빌드의 터치 동작은 네 해상도 GUI 검사와 새 Web 터치 검사로 확인했다. 마지막 영상 실행 시 검사 도구 수정이 있었던 `source_dirty` 값도 원자료에 그대로 보존한다.

선택한 캡처는 `docs/images/research-lab/`에 보관한다. `chromium-*`는 Web 터치 에뮬레이션이고 나머지는 Linux Godot이며, 실기기 캡처가 아니다.

## 사용자 체험 순서

1. Mac의 `KMH/05_게임` 아래 새 폴더에 Web ZIP을 풀고 **`iPhone 체험 열기.command`**를 연다. 설치한 Godot을 응용 프로그램 폴더에 둔다.
2. iPhone은 Mac과 같은 Wi-Fi에 연결하고 표시된 Mac 주소를 Safari 일반 탭에서 연다. Mac의 서버 창은 열어 둔다. 로컬/네이티브 저장은 서로 자동 공유되지 않는다.
3. 기존 진행에서 3장을 마친 뒤 **병원 밖 → 연구소 예정지 → 1,800만 설립**. 6점이 한 번 지급되는지 확인한다.
4. 연구 하나를 **500만+6점**으로 시작한다. 시작 다음 운영일을 마치고, 그다음 날 CT 또는 계획 검토가 4초가 되는지 확인한다.
5. 앱/페이지를 다시 열어 자금·점수·연구가 유지되는지 확인하고 상단 재생으로 이어간다. Android는 기존 앱을 삭제하지 않고 새 APK로 업데이트한다.
