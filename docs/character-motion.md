# 캐릭터 동작과 조작 피드백 · 2026-11-05 KST

기준 커밋은 카메라 안정화를 완료한 `5eb1c78`이다. 가로 화면, 고정 카메라 방향, 기본 운영 시점과 사용자가 요청하는 상세 보기를 유지한다. 경제·스토리·시설은 추가하지 않았다. [영상 검토 페이지](character-motion.html)에서 실제 엔진의 구간별 시연을 본다.

## 이동과 대기

환자 몸 방향을 이동 방향으로 점진적으로 보간한다. 보행 주기는 경과 시간만으로 돌리지 않고 실제 표현 위치의 이동 거리에서 계산한다. 멈출 때 보행 강도가 가라앉는다. 같은 구조를 네 환자에게 사용한다. 완전한 발 접지 IK는 아니며, 기존 Blender 부위 피벗을 이용한 게임용 보행이다.

대기 중에는 작은 호흡, 짧은 눈 깜박임, 쉬는 간격이 긴 주변 보기를 적용한다. 환자와 직원마다 시작 위상을 달리한다. 눈 흰자와 홍채의 기존 메시 표면만 접히는 작은 셰이더를 사용한다. 피부·머리·안경 재질과 모델은 보존한다. 기존 네 좌석과 첫 환자의 책은 유지하며, 앉기와 자리에서 일어나기를 짧게 연결한다.

실제 메시 검사에서 의자 사이와 출입구의 간섭을 확인했다. 앞줄 의자는 0.5, 뒷줄은 0.15 게임 단위 뒤로 이동해 통로를 확보했다. 계획실 문을 가로지르던 짧은 복도 손잡이는 제거했다. 별관 연결 통로 가까운 화분은 0.45 단위 안쪽으로 옮겼다. 좌석 번호와 시뮬레이션의 대기 위치·waypoint·속도·장비 예약은 그대로다. 표현 위치만 좌석 앞·침대 옆·치료실 앞의 짧은 안전 경로를 따른다. 이 차이는 새 저장 필드 없이 기존 위치와 경로로 재현한다.

## 검사·치료 전환

도착 → 준비 → 눕기 → 장비 이용 → 일어나기 → 기존 다음 목적지 이동을 표현한다. 준비 0.15초, 기울이기 0.6초와 침대 정렬 두 구간 각 0.3초로 총 1.35초다. 반대 순서로 일어난다. 최종 눕기 높이, 몸통·매트리스 간격과 머리·베개 위치는 이전에 검증한 값을 유지한다.

처음에는 최종 자세만 안전한 대각선 전환이 CT 외장 또는 치료 헤드를 통과하는 것을 발견했다. CT는 열린 앞쪽에서 몸을 정렬한 다음 들어간다. 치료기는 Blender에서 곡선 암과 헤드를 실제 별도 메시 `TreatmentHead`로 분리했다. 환자 승하차 전에 0.55 단위 올라가고, 정렬을 마친 뒤 0.4초 동안 내려온다. 본관·별관에 같은 구조를 적용한다. 치료 표시 광선은 장비가 내려온 실제 이용 구간에만 보인다.

운영 상태는 새 상태로 교체하지 않는다. `ct_scan` 5초와 `treatment` 30초의 처음·끝에 표현 전환을 포함한다. 전환 중 카드는 ‘CT 준비 중’, ‘치료 준비 중’, ‘검사/치료 마무리 중’을 보여 준다. 이 버전에서 순수하게 누워 있는 시간이 장비 이용 시간 전체와 같다는 의미는 아니다. 예약 해제·다음 업무·수입 지급은 기존 이용 시간이 끝났을 때만 발생한다.

## 민지와 조작 반응

민지는 기본 호흡·깜박임에 더해 접수가 실제로 성공했을 때 짧게 고개를 끄덕이고 안내 손짓을 한다. 가까운 귀가 환자에게 한 번 인사한다. 중복 지시나 실패한 접수는 반응을 다시 만들지 않는다. 얼굴과 안내 손을 볼 수 있도록 접수대 안 위치와 모니터 간격을 보정했다.

선택 표시를 민트색으로 바꾸고 시뮬레이션 시간 0.24초 동안 부드럽게 나타나게 했다. 기존 카드 교체, 버튼 눌림 스타일, 업무 상태에 따른 비활성화·사유, 완료 단계 체크를 그대로 사용한다. 선택은 업무 실행과 분리한다. 새 음원은 추가하지 않았으며 무음에서도 링·카드·버튼·체크로 반응을 확인할 수 있다.

치료가 끝나면 ‘오늘 일정 완료’와 작은 체크가 잠깐 나타나고 기존 귀가 경로를 따른다. 완료 수입은 기존 `paid` 검사로 한 번만 지급한다. 완료 표시가 입력을 막거나 팝업을 열지 않는다. 귀가 중인 환자를 따라 자동 카메라가 움직이지 않게 했다.

## 일시정지와 저장

보행·호흡·눈·업무 손짓·완료 표시의 시간은 시뮬레이션에 전달하는 delta를 사용한다. 일시정지와 병원 밖에서는 멈추며, 배속에서는 함께 빨라진다. 카메라의 UI 전환은 기존 0.42초를 유지한다.

검사·치료 자세와 장비 위치는 저장된 상태·elapsed·위치로 다시 계산한다. 저장 형식 v2, 소유권 검증, FIFO, 수입 규칙은 변경하지 않았다. 준비·눕기·이용·일어나기 각 단계의 복원과 두 치료실을 별도로 검사한다. 호흡·시선 같은 장식적인 위상은 새 실행에서 다시 시작하며 저장하지 않는다.

## 검증과 전달

운영 회귀 검사, 실제 엔진 UI/카메라 검사, 별도의 동작 검사, Web 데스크톱/터치 에뮬레이션을 사용한다. 최종 수치와 소스·에셋·영상 해시는 [결과 JSON](character-motion-results.json)에 기록한다.

동작 검사는 일시정지, 1/2배속의 동일 거리·시간, 정지, 접수 중복 차단, 민지 반응, 선택 링, 자세 복원, 정산과 네 환자 귀가, 두 치료실 사용을 포함한다. 60Hz로 이동·전환 중 머리·몸통·손의 작은 구형 검사체를 실제 병원 삼각형과 비교하며, 움직이는 치료 헤드의 실제 높이도 반영한다. 이것은 모든 신체 정점이나 옷·머리카락 사이의 완전한 충돌 검사가 아니다.

영상은 정상 1배속, 자동 입력 시연이다. 실행·체크포인트 배치를 기다리는 녹화 앞부분의 정지 프레임만 제외했다. 각 플레이 구간은 자르거나 이어 붙이지 않았고 시간 건너뛰기나 배속이 없다. 치료와 동시 치료 영상은 일반 접수·계획 지시·시간 진행·정상 구매로 만든 체크포인트에서 시작한다. 시연 도중 상태·수입·소유권을 직접 바꾸지 않는다. 실행 환경은 Linux Godot 4.6.3 Compatibility/Mesa llvmpipe다. 녹화 24fps는 실제 모바일 성능 측정이 아니다. Mac/iPhone Safari 실기기와 공개 Pages 접속은 미검증이다.

남은 임시 표현은 부위 피벗 보행과 몸 전체를 기울여 연결하는 간략한 승하차 동작, 앉은 다리 메시 전환이다. 개별 무릎·발 접지·손 짚기 IK 및 직원의 자유 이동은 구현하지 않았다. 기존 작은 정적 AO는 유지하므로, 이동된 가구 주변의 접촉 음영을 다시 굽는 후속 미술 정리가 가능하다. 현재 작업의 완료 여부와 실제 확인한 화면은 영상과 검사 결과로 확인한다.

주요 파일: `godot/scripts/actor.gd`, `character_motion.gd`, `world.gd`, `patient_feedback.gd`, `main.gd`, `godot/assets/shaders/blink.gdshader`, 두 병원 `.blend`/GLB, `tools/art/prepare_motion_assets.py`. 기존 환자·간호사 Blender/GLB, 조명 환경과 기본 재질은 유지했다.
