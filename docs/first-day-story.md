# 첫날 튜토리얼과 첫 환자 이야기 · 다시 켜진 간판

새 게임에서 민지와 김영수를 만나 실제 선택 → 접수 → CT → 계획 맡기기 → 치료 → 오늘 일정 완료 → 귀가를 익힌다. [실제 엔진 영상](first-day-story.html)과 [Mac 실행 안내](mac-play.md)를 함께 본다.

## 구현

- `godot/scripts/first_day_story.gd`: 첫날 장면 ID, 본 대사·현재 줄·선택 경험·진행 단계. 시간 경과로 행동을 완료하지 않고 실제 환자 상태와 기존 정산 결과를 읽는다. 시뮬레이션을 실행하거나 수입·증축·예약을 변경하는 권한이 없다.
- `godot/scripts/main.gd`: 기존 초상·아이보리 패널·민트 버튼을 사용한 짧은 대화, 다음/현재 대화 건너뛰기/안내 끄기, 실제 버튼 테두리와 행동 안내. 환자 목록을 열면 대화 패널을 잠시 숨겨 목록을 가리지 않는다. 이미 접수·계획을 시작했다면 지난 요청을 종료한다. 카메라 이동 명령은 추가하지 않았다.
- `godot/scripts/save_store.gd`: 기존 v2 저장에 선택 필드 `first_day_story`를 추가한다. 운영 데이터 형식과 환자 예약 복원 규칙은 유지한다. 필드가 없는 기존 저장에는 튜토리얼을 강제로 시작하지 않는다. 해석할 수 없는 이야기 데이터가 있으면 기존 손상 저장 처리처럼 파일을 보존하고 쓰기를 차단한다.
- `godot/tests/test_story.gd`, `test_story_ui.gd`, `record_story.gd`: 저장·상태 전환·실제 UI 입력·1배속 영상 시나리오. 기존 회귀 시나리오는 `--qa`로 이야기 없이 수행하고 새 검사는 `--qa --tutorial`로 실제 이야기 UI를 포함한다. 일반 실행에서는 새 게임 이야기가 켜진다.

대화는 운영을 멈추지 않는 작은 패널이다. 다음/건너뛰기는 현재 장면만 끝내고, **안내 끄기**는 이 저장의 첫날 이야기·강조·튜토리얼 안내 전체를 끈다. 환자 카드와 일반 대기 안내는 계속 작동한다. 행동을 기다리는 안내는 게임을 정지시키지 않는다. 플레이어의 일시정지 의도와 병원 밖·앱 포커스 이탈·앱 백그라운드 상태를 별도로 보관해, 임시 정지가 끝나도 플레이어의 일시정지를 해제하지 않는다. 저장을 불러오면 기존 정책대로 재생을 눌러 이어간다.

첫 치료가 실제로 정산되면 감사 대사와 선택적인 증축 안내가 이어진다. ‘병원 밖’ 오른쪽 예정지와 기존 증축 확인창에서 600만·두 치료실 효과를 확인한다. 자동 구매나 강제 화면 이동은 없다. 네 환자가 모두 귀가한 뒤 실제 완료 인원·진료비 합계·증축 여부를 보여주고 기존 다음 날 버튼으로 이어간다. 2일차에는 첫날 이야기 UI가 나오지 않는다.

## 기획 원문과의 차이

- [원본 인물 표](../reference/original-design.md)의 **박 원장(병원장)**과 **박 선생(선배 계획자)**은 서로 다른 인물이다. 합치거나 새 인물을 만들지 않았고 이번 대사는 민지·김영수에게 한정했다.
- [시즌 기획](../reference/season-one-design-v1.0.md)의 챕터 보상 300만·평판 +3, 다음 방문 안내·목재 기념품은 구현하지 않는다. 최신 요청대로 초기 900만, 진료비 200만, 증축 600만을 유지한다. ‘완치’ 표현과 아직 없는 재방문 예약 안내도 사용하지 않는다.
- 원문의 중요 대화 정지 규칙 대신, 이번 요청의 다른 환자 운영을 막지 않는 짧은 안내를 적용했다. 대화 자체는 정지를 바꾸지 않는다. 주요 상태가 앞서 진행되면 읽던 이전 행동 안내도 정리한다.
- ‘계획 검토’는 기존 **계획 맡기기** 버튼에 연결한다. 새 의료 판단·치료 체계·경제·연구·지도·결제 기능은 추가하지 않았다.

## 영상

모두 실제 Godot Compatibility 엔진에서 **자동 입력**, **정상 1배속**, 1280×720·24fps로 녹화했다. 직접 수동 플레이로 표시하지 않는다. 첫 인사는 새 게임부터 시작한다. 완료·마무리 영상의 시작 지점은 기존 공개 운영 동작과 시간 진행으로 준비한 체크포인트이며, 환자 상태·금액을 임의로 덮어쓰지 않았다. 영상 안의 병원 밖 전환은 기존 규칙대로 잠시 정지한다.

- [첫 인사·김영수 선택·접수·CT·계획 · 46초](media/story-welcome-1x.mp4)
- [첫 일정 완료·증축 안내·외부 예정지·구매 버튼 입력 · 29초](media/story-completion-1x.mp4)
- [네 환자 귀가·실제 첫날 기록·2일차 진입 · 20초](media/story-ending-1x.mp4)

각 MP4 옆의 `-results.json`에는 클릭 수·상태 추적·프레임 수를, `-checkpoint.json`에는 녹화 시작 상태를 남긴다. 반복 생성은 `python3 tools/run-visual-qa.py --movie --story welcome --output-dir artifacts/story-welcome`이며 `completion`, `ending`도 같은 방식이다. `--rehearsal`로 렌더 없는 입력 시나리오를 먼저 확인할 수 있다.

## 확인 범위와 남은 요소

구현 커밋 `764f582a429469bd169c6870222d4a78c3897415`에서 운영 51개, 동작 48개, 첫날 상태·저장 82개, 기존 화면·입력 172개, 이야기 UI 125개로 **총 478개** 검사를 통과했다. 데스크톱 Chromium 클릭과 844×390 터치 에뮬레이션에서도 실제 접수·IndexedDB 저장·이야기 단계 저장을 확인했다. 영상 세 파일은 전체 디코딩 검사를 통과했다. 녹화 전 일시정지된 준비 프레임만 제거했으며 플레이 구간의 프레임 제거·배속 변경은 없다.

상세 검사와 최종 파일 해시는 [검사 결과](first-day-story-results.json)에 보관한다. Linux 소프트웨어 렌더러의 캡처·입력 검사이며 Mac GPU·Safari/iPhone 실기기 성능 측정이 아니다. 웹의 소프트웨어 렌더링은 느려 `--save-timeout 900`으로 실제 상태와 저장을 기다렸으며, 이 대기 시간은 게임 시간을 강제로 진행시키지 않는다.

초상은 기존 게임 초상을 재사용했고 음성·입 모양 애니메이션·대화 기록 다시 읽기 메뉴는 아직 없다. 안내를 끈 저장에서 다시 켜는 설정 메뉴도 이번 범위에 포함하지 않았다. 기존 저장은 운영을 그대로 이어가며 새 이야기는 새 게임에서만 시작한다. 전체 시즌·재방문·장식 보상은 후속 범위다.
