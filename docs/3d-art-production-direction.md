# 3D 캐릭터와 게임 화면 제작 지침

2026-11-20 KST. 사용자는 기존 2D 대화 초상과 단순한 게임 캐릭터보다 디테일하고 귀여운 **3D 스타일**을 요청했다. [시안 갤러리](../reference/art/3d-direction-v1/README.md)의 다섯 이미지를 제작 참조로 사용한다. 이번 커밋은 참고 이미지와 문서만 추가하며 모델 제작·게임 적용·실기기 검증 완료를 뜻하지 않는다.

## 1. 민지를 실제 게임 자산으로 제작

- 먼저 현재 민지 `.blend`, 메시, 텍스처, 리그, Unity 프리팹을 확인한다. 원본은 보존하고 추적 가능한 신규 버전으로 개선한다.
- 캐릭터 시안에서 갈색 단발, 눈꺼풀과 눈의 입체감, 둥근 볼과 작은 코, 따뜻한 입 모양, 흰 둥근 칼라, 민트 근무복, 해바라기 배지, 손과 운동화를 읽어낸다.
- 얼굴 디테일은 납작한 눈 스티커만 확대하는 방식으로 대체하지 않는다. 적절한 얼굴 기하·눈·눈꺼풀·표정 제어를 제작한다. 머리는 작은 털을 대량 추가하기보다 주요 머리 덩어리와 방향, 적당한 광택으로 표현한다.
- 시안의 체형은 제안이다. 기존 2.5~3등신 인게임 방향과 시안의 더 긴 신체 비율 사이의 차이를 기록하고, 운영 카메라에서의 작은 캐릭터와 대화 확대를 둘 다 확인해 자연스럽게 정한다. 어른인 병원 직원의 정체성을 유지한다.
- 피부·머리·옷·신발의 재질을 구분한다. 모든 표면을 같은 플라스틱 광택이나 회색 무광으로 만들지 않는다.
- 기본 미소, 인사, 설명, 기쁨, 걱정 표정과 눈깜빡임을 순차 연결한다. 걷기·대기·업무·인사 동작의 손·발과 바닥 접촉을 확인한다. 오디오나 립싱크는 준비되지 않았다면 완료로 표현하지 않는다.
- 환자도 같은 디자인 규칙을 적용한다. 민지와 환자의 머리 비율·눈 스타일·재질이 서로 다른 게임처럼 보이지 않도록 한다.

## 2. 대화 캐릭터와 3D 공간의 연속성

- 우선 같은 민지 자산과 리그를 대화용 카메라/RenderTexture로 표시하는 방식을 검토한다. 운영용·대화용 LOD를 사용한다면 얼굴과 의상 정체성, 원본과 내보내기 관계를 유지한다.
- 일러스트 또는 전체 시안 한 장을 붙여 놓고 3D 캐릭터를 완성했다고 보고하지 않는다. 사전 렌더 초상을 임시 사용하면 명시하고 실제 모델 결과를 별도로 제시한다.
- 작은 인게임 인물에는 읽히는 동작과 실루엣, 큰 초상에는 표정·눈·손을 강조한다. 단순히 작은 모델을 확대해 저해상도 얼굴을 드러내지 않는다.
- 기존 대화 ID·저장·건너뛰기·다시 보기·일시정지 복원과 실제 버튼 입력을 유지한다. 초상과 대화창을 닫으면 게임 공간과 입력이 정상으로 돌아와야 한다.
- 3D 초상 배경/알파, 조명 레이어, 카메라 간섭, UI 정렬을 검증한다. 추가 카메라 비용은 실제 측정한다.

## 3. 내부·외부·지도 각각의 제작 범위

### 병원 내부

시안의 크림 벽·원목·코랄 대기석·민트 장비와 선명한 색 구분을 적용한다. CT와 LINAC은 실루엣부터 구분한다. 수많은 화분보다 환자·통로·장비의 가독성을 우선한다. 가까운 벽과 큰 장비가 선택 환자나 조작을 가리지 않게 한다. 기존 FIFO·시설 예약·장비 승하차를 아트와 함께 검증한다.

### 병원 외부

모델의 기본 큐브 덩어리만 둔 상태에서 벗어나 지붕·창틀·입구·간판·정원·보행 접근을 일관된 형태로 제작한다. 증축 부지, 미리보기, 구매 후 실제 건물과 운영 시설 증가를 연결한다. 층수와 장식은 경제·시설 수와 별개로 기획에 맞게 조정한다.

### 지역 지도

세 정보 카드를 지도 완성으로 취급하지 않는다. 내륙·강변·해안 지형과 병원 모델, 연결 경로, 선택·운영·잠금 상태를 구현한다. 별도 정보 패널은 선택 노드에 연결한다. 기존 병원 식별자·개원 조건·전환·저장 규칙을 유지하며 지형을 통해 새로운 이동비나 시간 규칙을 임의로 만들지 않는다.

## 4. 공통 UI와 폰트

- 크림색 둥근 프레임, 골드 테두리, 선명한 청록색 글자, 민트 주요 버튼, 코랄 강조를 적용한다. 실제 색 대비와 입력 상태를 확인한다.
- 아이콘은 작은 입체 소품처럼 보이되 같은 시점·광원·테두리 스타일을 갖도록 만든다. 글자는 실제 UI로 표시한다.
- 9-slice 등 해상도 변화에 견디는 패널 구조를 사용한다. 동일한 스타일을 운영·연구·직원·꾸미기·정산에 적용하되 기능을 빠뜨리지 않는다.
- 이미 확인한 주아·본문 폰트 라이선스를 보존한다. 글자를 이미지에 구워 넣어 한글 줄바꿈이나 현지화를 막지 않는다.
- 16:9 및 긴 가로 화면의 얼굴·손·대사·버튼 안전 영역을 확인한다. 중요 정보의 과도한 자동 축소를 피한다.

## 5. 제작 순서와 완료 증거

1. 최신 코드와 원격 참조 자료를 기존 로컬 변경을 보존하며 통합한다. 독립된 `main` 문서 커밋과 Mac 검토 브랜치가 있을 수 있으므로 강제 reset/push하지 않는다.
2. 민지 하나를 개선해 실제 Unity에서 운영용 크기와 대화 클로즈업으로 검증한다. 그 다음 다른 인물과 병원 내부에 확장한다.
3. 내부→외부·증축→지역 지도 순서로 실제 기능과 새 아트를 연결한다. 한 장면의 미세 조정만 반복하며 전체 작업을 보류하지 않는다.
4. 블렌더 원본 또는 실제 제작 프로젝트, 내보내기 설정, Unity 모델·재질·리그 연결을 추적 가능하게 남긴다. 사용한 도구가 없으면 그 제약을 기록한다.
5. 새 메시의 폴리곤 수·재질 수·텍스처 크기·렌더 비용을 측정한다. URP 모바일 목표를 유지하며 HDRP·무제한 실시간 광원·고해상도 텍스처를 전제하지 않는다. 생성 이미지의 렌더 품질을 모바일 실시간 성능으로 주장하지 않는다.
6. 실제 Unity 스크린샷과 정상 속도 영상으로 모델 회전/표정, 걷기, 대화, 병원 내외부, 지도를 보여준다. 생성 콘셉트와 실시간 게임 캡처를 명확히 표시한다. 영상은 프레임 상하 방향과 실제 재생까지 확인한다.
7. 기존 게임 규칙·정산·구매·보상·저장·복원 회귀를 검사한다. 추가 기능이나 숫자를 이미지에서 추측해 넣지 않는다.
8. 검증 단위로 커밋하고 공유 가능한 PNG/MP4를 저장소 지침에 맞게 보관한다. 원격에 없는 Mac 파일을 공유 완료라고 쓰지 않는다.
