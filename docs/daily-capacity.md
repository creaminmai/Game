# 별관 규모와 하루 예약량

2026-11-10 KST · 0.7.0-dev · Godot 4.6.3. 가로 화면의 실제 3D 병원 운영을 유지한다. 별관 600만 효과에 다음 날 예약 6명을 포함했다. 추가 요금·건설·운영비·예약 취소·만족도·분원은 없다.

## 플레이 방식

첫날은 항상 네 명이다. 별관이 없으면 다음 날도 네 명이다. 별관이 있으면 병원 일지의 **내일 예약 정하기**에서 다음 중 하나를 고른 뒤 **다음 날 시작**으로 확정한다.

| 선택 | 예약 | 모든 일정 완료 시 예상 진료 수입 |
| --- | --- | --- |
| 여유 있게 운영 | 4명 | 800만 |
| 예약 확대 | 6명 | 1200만 |

처음 기본값은 4명이며 최종 확정한 선택을 기억한다. 선택 변경·취소·창 닫기는 날짜·자금·예약·기본값을 바꾸지 않는다. 예상 수입은 선지급하지 않는다. 다음 날 연속 입력은 미완료 당일 조건에서 거절된다. 별관을 낮에 사도 오늘 예약은 유지된다. 첫 6명 선택의 민지 안내는 작은 패널 문구이고 안내를 끄면 표시하지 않는다.

상단 완료 표시는 **실제 귀가 / 당일 확정 예약**이다. 치료비는 기존처럼 치료를 마칠 때 한 번 지급한다. 귀가 중인 환자의 지급과 귀가 완료 집계는 별개다. 목록은 충분한 크기의 두 줄 항목과 터치 스크롤을 사용하며 도착 전 예약도 보인다. 여섯 번째 항목을 선택한 뒤 별도로 접수한다.

## 인물·통행

`patient_profiles.gd`에 원래 네 인물과 기존 날짜별 이름 순환을 보존했다. 일반 방문자 **윤태호**(남색 옷·짙은 갈색 머리·안경 없음), **오진우**(황토색 옷·밝은 갈색 머리·안경)를 추가했다. 분원 인물이나 이야기 보상과 관계없는 일반 환자다. 기존 Blender 환자 GLB와 모션을 재사용하고 실제 Godot 모델로 5·6번 초상을 렌더링했다. 새로운 전용 헤어 메시·얼굴 리그는 만들지 않았다.

기존 네 좌석을 유지하고 추가 두 명은 대기실 벽 쪽과 접수 공간 앞의 실제 빈 입석 위치를 사용한다. 입장 간격은 기존 6초다. 여섯 명 운영에서는 중앙 복도 양방향에 작은 통행 간격을 두고, 추가 환자의 계획실 경로를 기존 대기 위치 밖으로 돌렸다. 치료실 출입 통로를 귀가 환자가 사용 중이거나 본관 환자가 침대로 옮겨가는 짧은 동안에는 들어가는 환자가 기다린다. 다음 장비 예약은 정상적으로 유지되며 임상 업무 시간을 생략하거나 바꾸지 않는다. 대기 중에는 이동 거리가 0이므로 걷기 동작도 멈춘다.

카메라 방향·상태별 자동 추적 정책은 변경하지 않았다. 검사·치료 시간, 수입 200만, 자동 접수와 자동 계획 3초 준비도 그대로다. 방 2개에서 다른 환자를 치료하며, 수동 지시도 계속 가능하다.

## 저장과 과거 기록

기존 루트 저장 v2에 선택적 `daily_schedule` v1을 추가했다. 저장 위치·앱 식별자·기존 개발 서명을 유지한다. 사용자의 저장을 지우거나 초기화하지 않는다.

- `today_count`: 하루 시작 때 확정한 인원. 로드·낮 증축으로 늘어나지 않는다.
- `preferred_count`: 마지막으로 확정한 다음 날 선택. 아직 선택 중인 초안은 저장하지 않는다.
- `closed_counts`: 실제 마감의 날짜 순서별 방문 수. 마지막 환자 귀가 때 한 번 추가한다.
- `legacy_through`: 0.6.0의 고정 4명 불변 조건으로 검증할 수 있는 과거 구간만 나타낸다.
- `legacy_paid_total`: 과거 저장이 가진 실제 누적 지급 카운터를 보존한다. 과거 모순을 새 돈으로 보정하지 않는다.
- `six_seen`: 첫 6명 확정 여부.

**지난 날짜 × 4**는 `daily_schedule`이 없는 기존 저장의 고정 인원 구간을 처음 이전할 때만 사용한다. 새로 운영한 날은 항상 `closed_counts`를 합산한다. 챕터 2의 누적 방문과 챕터 3의 업무 출처 기록 검증도 해당 날짜별 실제 인원을 사용한다. 과거 일부 방문만 확인 가능한 `legacy_partial` 저장의 진행도는 그대로 유지하고 불확실한 방문을 임의로 늘리지 않는다.

0.6.0에서는 별관을 보유해도 진행 중인 네 명을 유지한다. 자금·연구·교육·위임·완료 챕터·당일 지급·업무 출처를 보존하며, 다음 정상 날짜 전환부터 4명/6명을 고른다. 실제 이전 버전의 연구 적용 중 QA 저장을 `tests/fixtures/capacity-legacy-0.6.0.json`에 보관했다. 사용자 저장이 아니며 이전 소스의 정상 명령으로 만든 검토용 자료다.

## 챕터·연구·정산

첫날 챕터는 기존 네 명, 2장 목표는 누적 방문 12회, 3장 목표는 두 자동 업무를 거친 방문 4회다. 목표가 낮에 달성되어도 일지는 여섯 명 모두 귀가해야 준비된다. 연구 생산도 정상 마감당 **4점**이며 환자가 여섯 명이어도 늘어나지 않는다. 연구 진행·완료·다음 날 적용은 같은 마감/날짜 전환 이벤트를 사용한다.

정상 명령으로 교육·연구 없이 진행한 기준 경로:

| 날 | 예약·귀가 | 진료 수입 | 별관 지출 | 마감 자금 | 누적 방문 |
| --- | --- | --- | --- | --- | --- |
| 1 | 4 | 800만 | 600만 | 1100만 | 4 |
| 2 | 6 | 1200만 | 0 | 2300만 | 10 |
| 3 | 6 | 1200만 | 0 | **3500만** | **16** |

일지·입금·대화·로드로 방문 수가 증가하지 않는다. 여섯 명 중 네 명이 귀가했거나 마지막 환자가 귀가 중인 상태에서는 마감·연구 생산·다음 날 진행이 불가능하다.

실제 GLB 삼각형과 머리·몸통·손 구체를 이용한 30Hz 검사에서 새 환자의 가구 접촉을 확인한다. 모두 대기 후 일괄 접수, 도착 즉시 수동 지시, 자동 위임 세 경로를 검사한다. 무작위 모든 입력 순열이나 일반적인 충돌 회피 AI를 검증했다는 뜻은 아니다.

UI는 **844×350 / 844×390 / 915×412 / 1280×720**에서 실제 Godot 렌더와 입력을 확인한다. 작은 화면의 좌우 47·하단 21 픽셀 안전 영역은 모사값이다. 실제 휴대폰의 노치·발열·FPS·배터리와 Android/iPhone 실행은 미검증이다.

## 영상·빌드 전달

[영상·캡처 보기](daily-capacity.html). Linux Godot 실제 실행·자동 입력·정상 1배속이며 24fps는 녹화 형식이다. 녹화 시작 저장과 중간 구간은 정상 운영 명령으로 준비했다. 자금·진료 상태·완료 횟수를 바꿔 만든 장면이 아니다. 전체 하루는 별도 자동 검증 기록으로 남긴다.

1. `docs/media/capacity-booking-1x.mp4`: 첫날 일지 → 6명 선택 → 다음 날 0/6. 22초 연속 구간.
2. `docs/media/capacity-flow-1x.mp4`: 여섯 명 대기·목록 → 직접 접수 → 민지 위임 → 직접 계획 → 두 치료실. 54초, 36초 이후 명시된 정상 운영 체크포인트로 한 번 전환한다.
3. `docs/media/capacity-journal-1x.mp4`: 마지막 귀가 → 6명·1200만 일지 → 다음 날 4명 선택 → 실제 테스트 파일 저장·복원. 25초 연속 구간.

빌드 식별·체크섬·검사 결과는 `daily-capacity-results.json`에 기록한다. Android와 Web은 0.7.0-dev/code700의 동일한 깨끗한 소스 커밋으로 내보낸다. APK는 설치 가능한 개발 서명 빌드이며 스토어 출시본이 아니다. 공개 Pages 게시와 실기기 실행은 별도 확인 항목이다.

Mac에서는 Web ZIP을 `KMH/05_게임` 아래 새 폴더에 풀고 `iPhone 체험 열기.command`를 실행한다. iPhone은 같은 Wi-Fi에서 도우미가 표시하는 Mac 주소를 연다. 이 클라우드의 localhost 주소는 휴대폰 접속 링크가 아니다. 기존 Android 앱은 삭제하지 않고 새 APK로 업데이트한다. 웹·Android·Mac Godot 저장은 자동으로 공유되지 않는다.

Web 원격 백업은 `gh-pages`의 `5d1f33314947d6aa3cbf4c656bbe1560d4c67062`이며 빌드 소스 `fd09e02`를 가리킨다. 원격 브랜치 SHA를 확인했다. GitHub Pages의 공개 게시·접속 성공을 뜻하지 않는다. 소스 `fd09e02`도 main에 푸시해 원격 일치를 확인했다. 최종 검토 커밋에는 영상·캡처·검사 기록·추가 경계 검사만 더하며, 빌드의 게임 소스·에셋은 바꾸지 않는다.
