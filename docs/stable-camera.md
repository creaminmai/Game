# 안정적인 기본 카메라 · 2026-11-05 KST

비교 기준은 `5e60676`이다. 상태 안내·환자 카드·말풍선·재질·치료 자세와 운영 규칙을 유지하며 카메라의 동작과 기본 구도를 수정했다. 경제·스토리·시설·저장 형식은 변경하지 않았다.

## 기본 시점과 화면 점유

기본 화면은 접수·대기, CT, 계획실, 치료실과 중앙 동선을 함께 보여 준다. 이전처럼 선택 환자의 상태별 방 경계를 맞추지 않는다. 병원 뒤쪽의 높은 벽과 앞쪽 바닥을 포함하는 전체 경계로 구도를 잡고, 상단 HUD와 실제 조작 대상 사이의 여유를 따로 확인한다. 앞쪽 바닥·화단은 하단 메뉴 뒤까지 확장될 수 있다.

960×540 논리 화면에서 기본 카메라 크기는 17.665→14.331이다. 같은 모델의 선형 화면 크기는 약 23% 커졌다. 증축 후 기본 크기는 21.825→15.504로 약 41% 커졌다. 이 비율은 같은 각도에서 정사영 확대율을 비교한 값이며, 화면의 색칠된 픽셀 비율을 뜻하지 않는다. 기본·카드·증축 후 화면은 [전후 비교](stable-camera.html)에 보관한다.

## 선택과 자동 이동

카드를 열거나 환자를 바꿀 때 현재 확대율을 유지한다. 화면 안에 보이는 환자는 카메라를 움직이지 않는다. 선택 환자의 얼굴이 HUD·카드·하단 조작부를 제외한 영역 밖으로 나가면, 같은 확대율로 가장 가까운 안쪽까지 이동한다. 작은 안쪽 여유를 두어 경계에서 반복 이동하는 현상을 줄였다. 창 크기 변경·병원 안팎 전환·증축 후 기본 보기에는 해당 화면의 구도를 다시 계산한다.

목록에서 환자를 선택한 경우에는 목록을 닫고 카드 배치를 갱신한 뒤 가림을 판단한다. 이전 목록의 너비 때문에 이미 보이는 환자에게 불필요하게 이동하지 않도록 별도로 검사한다.

자동 이동과 요청한 상세 확대는 0.42초 동안 시작과 끝이 부드럽게 이어진다. 드래그 또는 줌 입력은 진행 중 전환을 즉시 중단하며, 이후 환자 상태 갱신이 사용자의 카메라를 덮어쓰지 않는다. 환자 재선택은 화면 밖 환자를 찾는 동작을 다시 허용하지만 현재 확대율은 보존한다.

카드 아래 **환자 보기**는 사용자가 요청한 상세 확대다. 진료 상태가 바뀌어도 다른 방에 맞춰 자동으로 다시 확대하지 않는다. 하단 **병원** 버튼은 안정적인 기본 운영 시점으로 돌아온다. 카드의 닫기 버튼은 카드만 닫으며 구도를 바꾸지 않는다.

## 검증과 영상

정상 1배속 영상은 한 환자를 선택한 채 접수 → CT → 계획 → 치료를 진행한다. 상세 확대를 요청하는 44초 전까지 카메라 위치·확대율을 매 프레임 비교하고, 단계별 좌표를 기록한다. 44초에는 환자 보기, 49초에는 병원 버튼을 실제 입력으로 누른다. 입력은 자동화한 시연이며 사용자의 수동 플레이테스트가 아니다.

카드 열기의 확대율 보존, 화면 안 환자 선택의 위치 보존, 상세 보기와 복귀, 전환의 중간 프레임, 화면 밖 환자에게 필요한 최소 이동, 실제 상태 변경 후 수동 드래그·줌 보존을 검사한다. 기존 운영·증축·동시 치료·다음 날·저장 복원과 CT/두 치료실의 자세·얼굴 선택 검사도 유지한다. 최종 결과는 [검사 JSON](stable-camera-results.json)과 [검증 기록](validation.md)을 본다.

Linux Godot 4.6.3 Compatibility와 Chromium WebGL/터치 에뮬레이션을 사용한다. 실제 Mac/iPhone Safari의 가독성·성능·화면 안전 영역과 공개 Pages 접속은 별도 검증이 필요하다. 가로 화면 기준을 유지하며 세로 화면은 회전 안내를 제공한다.
