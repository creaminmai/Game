# 현재 제작 기준과 기획 메모

## 챕터 1·2 진행 적용

첫날 네 명의 실제 귀가와 일지를 1장 완료로 연결한다. 2장은 치료별관·서로 다른 환자의 실제 동시 치료·누적 방문 일정 12회다. 첫날부터 증거를 수집하고 수동/민지 위임 모두 같은 조건을 적용한다. 원문 챕터 자금·평판 보상과 김영수 나무 장식은 이번에 지급하지 않는다. 900/200/600 경제, 첫날 이야기, 위임 선택, 안정적인 카메라를 유지한다. [구현·저장 복원·검사](chapter-progression.md)를 참고한다.

2026-11-03 UTC에 사용자가 두 기획안을 제공하며 저장하고 이후 개발에 참고하도록 요청했다. 원문 전체는 [기획 보관 목록](../reference/README.md)에 있으며, 이 문서는 작업 재개 시 먼저 읽을 요약과 적용 기준이다. 문서에 있다는 이유로 기능을 구현 완료로 표시하지 않는다.

## 우선 적용하는 결정

- 실제 3D 공간, 고정된 비스듬한 카메라, 크림·밝은 목재·민트·코랄·식물·따뜻한 빛을 가진 A+C 방향.
- 사용자가 대화에서 승인한 **가로 화면**을 유지한다. 새 원문의 표에는 세로로 적혀 있지만 원문은 보존하고 현재 화면 방향을 되돌리지 않는다. 방향 변경은 이후 사용자의 명시적인 결정에 따른다.
- 사용자의 체험 기기는 Mac/iPhone이며 웹 체험과 실제 플레이 영상을 우선한다. 최종 Android/iOS 출시 목표와는 구분한다.
- 매 작업의 검증 후 별도 요청 없이 main에 커밋·푸시하고 원격 SHA를 확인한다. 플레이 변화가 있으면 실제 실행 영상 또는 검증된 체험 빌드를 제공한다.
- 현재 운영 로직과 저장을 보존하며 아트를 발전시킨다. 전체 콘셉트 이미지를 게임 배경으로 붙이는 방식은 사용하지 않는다.

## 첫 시즌의 목표와 범위

본원 1곳·국내 분원 1곳·가상의 해외 해안 도시 협력병원 1곳·중앙 연구소를 연결한다. 로컬 싱글플레이로 일반 플레이는 오프라인에서도 가능하게 한다. 8개 챕터와 9개 연구를 갖추고 엔딩 이후 자유 운영을 제공한다. 3~5시간 / 24~32운영일은 조정 목표이며 달성했다고 주장하지 않는다.

기본 흐름은 환자 방문 → 접수 → 필요한 CT·계획 → 치료 → 오늘 일정 완료 → 수입·평판 → 직원·장비·증축·연구 투자다. 성장 순서는 본원 안정화 → 자동 운영·위임 → 연구소 → 국내 분원 → 지역별 운영 개선 → 해외 협력병원이다.

첫 시즌의 건설은 정해진 부지와 모듈을 선택한다. 자유 도시 건설·모든 가구의 자유 배치·온라인 협동·계정 기반 클라우드 저장은 이후 범위다. 새 병원도 실제로 들어가 환자와 직원을 볼 수 있어야 한다.

## 향후 기능을 설계할 때 지킬 규칙

- 오늘 일정과 전체 치료 과정을 구분한다. 3/5/7회 과정은 게임용 제안이며 첫 방문 이후에는 기본적으로 접수·치료를 진행한다. 재방문 예약을 먼저 확보한다.
- 이동 중 장비 예약과 실제 사용을 구분하고 중복 배정을 막는다. 대기 이유·앞 순서·가능한 행동을 설명한다. 이동시간을 대기시간에 넣지 않는다.
- 직접 계획은 선택형 5×5 추상 격자 퍼즐이다. 시간 제한 없이 후보 5개 중 2개를 고르고 검수된 고정 문제 10개부터 만든다. 자동 계획만으로도 시즌을 끝낼 수 있어야 한다.
- 직원 채용·교육으로 접수 자동화 → 계획 자동화 → 운영 위임을 해금한다. 분원 전에는 위임 기능이 필요하다. 수동 조작과 자동 조작을 중복 처리하지 않는다.
- 세 병원은 같은 날짜·시각과 운영 규칙을 사용한다. 현재 병원만 3D로 표시하며 화면 밖 병원도 같은 시뮬레이션을 진행한다. 전환 중에는 전체 시간을 멈추고 이전 재생 상태로 복귀한다.
- 연구는 자금·연구점수·운영일을 사용한다. 계획·장비·교육 3계열의 I→II→III, 총 9개다. 효과는 다음 날 적용하고 빈 날 넘기기로 점수를 얻지 않게 한다.
- 수입·구매·보상·정산에는 거래 식별자를 두어 한 번만 처리한다. 운영비 부족은 무이자 미납으로 관리하고 기본 진료를 영구 차단하지 않는다.
- 여러 병원·환자 과정·연구·이야기·설정을 저장하며, 원자적 교체와 직전 정상 저장을 보관한다. 기존 v2 저장은 실제 내용을 검토한 이전 규칙 없이 초기화하지 않는다.
- 중요한 대화·퍼즐·전환 중 시간 정지, 대화 ID별 반복 방지, 짧은 말풍선, 다시 읽기와 안전한 재개를 제공한다.
- 아트의 다음 기준: 2.5~3등신, 표정·인사·걷기·앉기·눕기·업무 동작. 민지는 갈색 단발·친근한 표정·청록 근무복의 고유 인물로 다듬는다. 현재 민지 모델은 갈색 단발·청록복·약 2.7등신으로 다듬었으며, 최종 얼굴 리그와 표정 연기는 남아 있다.
- 중급 모바일 30fps는 목표다. 낮음/기본 그래픽, 충분한 터치 영역, 색 외의 상태 표시와 접근성을 포함하고 실제 기기에서 검증한다.

수치·가격은 원문에 명시된 구현용 기본안이다. 예를 들어 360초 영업일, CT 12/16/20초, 자동 계획 18/24/30초, 치료 40/48/56초를 현재 프로토타입에 즉시 덮어쓰지 않는다. 관련 시스템을 개발할 때 데이터로 옮기고 경제·진행 테스트로 조정한다. 현재 5/5/30초와 첫날 임시 경제는 별도 검증 기준으로 남아 있다.

## 수익화 기준

첫 시즌은 결제 없이 엔딩까지 진행한다. 접수·계획 자동화, 필수 연구·증축을 일반 플레이로 해금한다. 환자 결과나 직원의 어려움으로 결제를 압박하지 않는다. 기본 병원과 무료 꾸미기·스토리 기념품도 충분히 보기 좋게 만든다.

후보 상품은 정원·대기실 테마, 이후 의상과 **완성된** 추가 이야기다. 가격 예시 4,900원·3,900원·9,900원부터는 검증용 제안이며 실제 상품·스토어 설정은 아직 없다. 유료 확률형·에너지 충전·즉시 연구 완료 구매를 첫 출시에서 제외한다.

먼저 무료 꾸미기를 경험하고 내 병원에서 미리보기로 결과를 확인하게 한다. 첫 15분에는 능동 추천을 하지 않고 첫 증축과 무료 꾸미기 이후부터 작은 안내로 제안한다. 자동 추천은 실제 날짜 기준 하루 최대 1회·주 최대 2회, 닫은 같은 상품은 7일간 재노출하지 않는 제안이다. 스토리·튜토리얼·직접 계획·구매 직후에는 추천하지 않는다.

공통 꾸미기는 보유 병원 전체에서 사용하고 운영 능력에 영향을 주지 않는다. 실제 가격·구성·적용 범위·영구 보유 여부와 구매 복원을 표시한다. 거짓 할인·마감 타이머를 사용하지 않는다. 스토어 권한과 진행 데이터를 분리하고 실패·환불로 병원 저장을 삭제하지 않는다. 별도 서버 없이 Android/iOS 간 구매 공유를 보장하지 않는다.

현재 작업은 기획 보존이며 결제·광고·상점 기능을 구현한 것이 아니다.

## 바로 다음 개발 단위

1. 진행 중인 대표 장면의 모델·재질·빛과 실제 환자 동선을 검증하고 영상·빌드를 보관한다.
2. 대기실·민지·첫 환자·CT 장면에서 챕터 1의 짧은 안내와 행동·완료 피드백을 연결한다. 큰 카드가 공간을 가리지 않도록 선택 UI를 다듬는다.
3. 첫 증축의 외관·내부·두 치료실 가동, 첫날 정산과 다음 목표까지 하나의 플레이 경험으로 완성한다.
4. 직원·자동 운영·교육과 여러 날 재방문을 만든 뒤 연구·퍼즐, 국내 분원, 해외 병원과 시즌 이야기로 넓힌다.

현재 완료 범위와 검증은 [프로젝트 상태](project-status.md)·[검증 기록](validation.md)을 본다. 전체 기획을 읽어야 할 때에는 요약만으로 판단하지 않고 보관한 원문 해당 절을 확인한다.

## 플레이 피드백 우선 · 2026-11-04

사용자는 기능 추가보다 현재 플레이의 구도·대기 안내·재질·치료 자세 개선을 요청했다. 선택 환자와 장비를 HUD 밖에 배치하고, 고정 공간 설명을 짧은 말풍선과 선택 카드의 상태별 이유로 정리한다. 원래 `playthrough.mp4`는 비교 기준으로 보존한다. 작업 결과에는 자동 6배속 외에 정상 1배속 30~60초 조작 영상을 제공하며, 자동 입력과 수동 플레이를 명확히 구분한다. [최신 플레이 검토](play-feedback.md)를 함께 읽는다.

## 안정적인 운영 시점 우선 · 2026-11-05 KST

상태 안내·환자 카드·치료 자세 개선을 유지한다. 기본 시점은 병원 주요 공간과 동선을 크게 보여 주며 환자의 진료 단계가 바뀌어도 방마다 자동 확대하지 않는다. 카드 열기는 확대율을 유지하고, 화면 밖 선택 환자에게만 최소 이동한다. 상세 확대는 명시적인 ‘환자 보기’ 조작으로 제공한다. 필요한 전환은 0.35~0.5초로 부드럽게 하며, 드래그·줌은 상태 갱신보다 우선한다. 이번 범위에는 경제·스토리·새 시설을 추가하지 않는다. 한 환자의 접수→CT→계획→치료 동안 기본 시점이 유지되는 정상 1배속 영상으로 확인한다. [최신 카메라 검토](stable-camera.md)를 기준으로 본다.

## 카메라 유지와 인물 반응 · 2026-11-05 KST

카메라 안정화를 먼저 `5eb1c78`로 검증·원격 백업한 뒤 캐릭터 동작을 진행했다. 대표 환자와 민지부터 이동 방향·보행·대기·접수 반응·장비 승하차를 개선하고 같은 구조를 다른 환자에게 적용한다. 임시 의료 동작과 실제 운영 상태를 구분하며 수입이나 예약을 표현 때문에 건너뛰지 않는다. 오늘의 완료는 ‘오늘 일정 완료’로 표시한다. 새 연구소·세계 지도·결제·경제는 이번 범위에서 제외한다. [현재 동작 검토](character-motion.md)와 구간별 정상 1배속 자동 입력 영상을 기준으로 후속 작업을 이어간다.

## 첫날 이야기 · 2026-11-07 KST

사용자는 Mac용 프로젝트 전달 뒤 ‘다시 켜진 간판’ 첫날 튜토리얼을 요청했다. 실제 환자 상태에 따라 민지·김영수의 짧은 대화와 기존 버튼 안내를 연결한다. 선택과 접수는 별도이며, 증축은 미뤄도 된다. 현재 900/200/600만 경제를 유지하고 원문의 추가 보상·재방문 안내는 적용하지 않는다. 박 원장과 박 선생은 서로 다른 원본 인물이며 임의로 합치지 않는다. 기존 저장에 첫날 이야기를 강제로 재생하지 않는다. [구현·검증·기획 차이](first-day-story.md)를 후속 기준으로 본다.

## 첫날 플레이의 완성도 · 2026-11-07 KST

최신 요청에 따라 첫 접수 전의 설명을 민지·김영수 각 한 줄로 줄이고 실제 버튼 옆 안내로 연결했다. 안내 설정의 끄기/다시 켜기, 실제 부지 선택과 구매 성공의 완공 표현, ‘오늘의 병원 일지’를 추가한다. 일지는 기존 정산·증축 거래만 기록하며 현재 경제를 바꾸지 않는다. 장부가 없는 이전 저장의 과거 지출은 ‘기록 없음’으로 표시한다. 소품·시설 종류·연구·지도·결제는 늘리지 않는다. [구현·결과 기준](first-day-polish.md)을 최신 기준으로 본다.
