# 햇살병원 Unity 작업 기록

## 시작 상태와 기준

작업 폴더는 `~/Developer/Game`이며 Unity 프로젝트는 `unity/`다. 시작 시 로컬 `main`은 `86a9afd`, `origin/main`은 `f4fe3dad`였다. GLB, 캡처 모듈, 검증 기록은 미커밋 상태였고, 에디터가 다시 직렬화한 두 설정 파일에도 공백 차이가 있었다. 원래 작업을 보존했고, 두 설정 파일은 이번 커밋 범위에서 제외했다. Godot, Blender 원본, 기존 저장 데이터는 그대로 보존했다.

Unity 6000.6.9f1 Apple Silicon, Metal, URP 17.6.0, 가로 화면과 고정된 비스듬한 카메라를 유지했다. 경제와 시간은 현재 Godot의 900만 시작 자금, 건당 200만, CT 5초·계획 5초·치료 30초를 적용한다.

## 화면에서 달라진 점

- 실제 3D GLB의 크림·민트·코랄·원목 구성을 유지했다. 밝은 면의 뿌연 인상을 줄이기 위해 환경광과 주광을 낮추고, 햇빛의 노란 기를 덜어 색과 그림자의 구분을 살렸다.
- 처음 Game 뷰의 HUD는 활성 상태였지만, 기존 PNG는 캡처 중 `GUI.enabled`가 전체 HUD에 적용돼 추가로 흐렸다. 이제 캡처는 색을 유지하면서 동작 처리만 잠시 막는다. 한편 건물 외곽 잘림은 Game 뷰와 PNG 모두에서 보이는 카메라 문제였다. 카메라 각도는 그대로 두고 렌더 영역을 HUD 사이에 배치했다.
- 둥근 민트 행동 버튼과 코랄 일시정지 버튼을 적용했다. 선택한 환자 태그는 민트로 채워지고, 일시정지 중에는 진행 버튼과 별도로 재생 안내가 나타난다. 도착과 계획 지시 대기에는 다음 행동을 표시한다.
- 환자 대기 위치를 의자 앞 통로로 옮기고 접수 직원은 카운터 끝에서 볼 수 있도록 했다. 원본 장비와 진료 자세를 유지하고, 이동·클릭 기준 콜라이더는 모델과 따로 두었다. 새로 조정한 대기 위치는 이 Unity 장면을 위한 배치 결정이다.

첫 환자의 새 HUD 수동 클릭과 장비 승하차 모습은 사용자 확인 대기다. 사용자의 후속 지시에 따라 두 항목을 기다리지 않고 4명 운영과 Unity 전용 저장을 이어갔다. 아래 후속 기록에 최신 검증 범위를 구분했다.

아침에는 Hospital 장면에서 새 Play를 한 번 시작해 **김영수 선택 → 접수 → 계획 지시 → 퇴장**을 직접 눌러 보면 된다. 이동 중 게임 화면의 일시정지 버튼을 한 번 사용하고, CT·치료 침대에 오르고 내릴 때 겹침이 눈에 띄는지, 퇴장 후 자금이 1,100만으로 유지되는지 확인할 수 있다. PNG와 영상은 아래 경로에 모았다.

## 후속 작업 · 첫날 4명 운영과 Unity 저장

### 완료한 구현

- **`bcf88ad` · 첫날 4명 운영.** 김영수·이정호·박상철·최민석이 0·6·12·18초에 도착한다. 환자별 이름, 위치, 단계와 선택을 분리했고, 이름 목록과 세계 모델에서 선택할 수 있다. 접수 후 CT, 계획 지시 후 계획 담당, 검토 완료 후 치료가 각 시설의 요청 순서대로 배정된다. CT와 치료기는 이동 중에도 예약을 유지한다. 공유 통로에는 구간별 진입 대기를 두고, 대기 및 계획실에는 별도 위치를 배정했다. 마지막 환자 치료 후에도 귀가까지 진행하고, 전원 귀가 후 결과에 4명·수입 800만·운영 자금 1,700만을 표시한다.
- **`e38ad43` · 저장·복원.** Unity의 `Application.persistentDataPath/UnitySaves/first-day.bin`에 버전 1을 저장한다. 시간, 수입과 귀가 수, 환자 단계·좌표·방향·경과시간·경로 지점·FIFO 순번을 복원한다. 시설 소유자는 저장된 단계에서 재구성하며, 중복 예약·수입 불일치가 있는 파일은 거부한다. 정상 저장은 임시 파일에 쓰고 디스크에 플러시한 뒤 교체하며 직전 정상본을 `.bak`에 둔다. 손상된 원본은 읽을 때 그대로 유지한다. 이후 사용자가 저장하면 별도 이름으로 원본을 먼저 보존한다. 저장을 불러왔을 때는 일시정지 상태에서 시작한다. 테스트는 임시 디렉터리를 사용한다.
- 변경 코드는 `PatientVisit.cs`, `DayRoutes.cs`, `HospitalGame.cs`, `HospitalRoom.cs`, `HospitalGame.Qa.cs`, `HospitalSave.cs`와 메타데이터, 재현 가능한 검사 `tools/test-unity-hospital.sh` 및 두 C# 검사 파일이다. 기존 Godot 코드, 원본 아트와 저장, 이전 PNG·영상은 보존했다.

## Mac 재부팅 뒤 실제 에디터 검증

재개 시 `HEAD`와 `origin/main`이 모두 `be85ff8`이었고 GitHub 커넥터에서도 같은 SHA를 확인했다. 이전 미푸시 7개는 이 기준에서 원격에 반영되어 있었다. 자동 직렬화 공백만 달랐던 설정 파일 두 개는 유지했다.

기존 Unity 6000.6.9f1 창을 사용했다. Play 중 스크립트 재컴파일 직후 이전 장면 상태에서 HUD의 모델이 null인 예외를 발견했다. 초기화되지 않은 런타임에서 Update·OnGUI를 건너뛰도록 수정하고, Play를 종료한 후 새 실행을 확인했다.

외부에 나가면 운영 시간이 멈추고, 내부로 돌아오면 이전 일시정지 상태를 유지한다. 첫 치료 완료 후 외부에서 600만을 확인 결제하면 별관 외관과 원본 GLB 치료실이 표시된다. 본원과 별관은 하나의 치료 FIFO를 공유하며 각각 한 명을 이동 중부터 예약한다. 첫날 예약 수는 그대로 유지하고, 마감 후 별관이 있으면 다음 날 4명 또는 6명을 선택한다. 일일 지출·수입을 분리했고 챕터 1·2는 귀가 수와 실제 동시 치료에 연결했다. 버전 2 저장은 별관·날짜·예약과 두 치료실 소유자를 보존하며 버전 1도 읽는다.

## 직원 위임과 연구

## 안내, 화면 안전 영역, Mac 통합 빌드

민지의 환영에서 첫 환자 선택, 계획 지시, 치료 완료, 별관, 첫날 마감까지 현재 상태에 맞춰 짧게 안내한다. 안내를 읽는 동안 운영 시간이 멈추고, 이미 본 안내나 안내 끄기는 버전 4에 저장한다. 이전 저장은 예전 안내를 다시 띄우지 않는다. HUD는 안전 영역과 카메라 영역을 사용하며, 상단 환자 카드가 뒤의 3D 환자 클릭으로 전달되지 않도록 영역을 분리했다. 팔·다리는 이동 거리에 따라 움직이고, 여러 환자를 복장 색과 이름으로 구분했다. 초기 Mac 빌드에서 발견한 미사용 후처리 셰이더 경고는 카메라가 사용하지 않는 후처리 데이터를 렌더러에서 제거해 해결했다.

- 독립 C# 검사는 **176개**, .NET과 Unity 내장 Mono 각각 통과. 기존 첫날부터 별관, 6명 운영, 직원 자동화, 연구소, CT 및 계획 4초 적용까지 실제 게임 코드로 연결했다.
- 실제 에디터에서 열린 안내를 격리 파일에 저장하고 정지 상태로 복원했다. 최신 아트와 안내가 들어간 코드로 F10 4명 회귀 시연이 통과했다. 초기 버전 1의 치료 지급 전후 저장도 버전 4 에디터에서 다시 복원해 각각 1,100만을 확인했다.
- 독립 [Mac 개발 빌드](../artifacts/unity-overnight/builds/SunshineHospital.app)를 Unity 6000.6.9f1에서 오류 0건으로 만들었다. Apple Silicon arm64 바이너리다. 첫 빌드를 Finder에서 열어 실제 3D와 한글 HUD를 확인했고, 환영 안내의 계속 버튼을 눌러 환자가 입장해 선택 안내가 표시되는 것도 관찰했다. 갱신 빌드에서 앱 창과 Metal 3456×2168 초기화, 후처리 경고가 사라진 플레이어 로그를 확인했다. 갱신 빌드의 화면 캡처는 ScreenCaptureKit 스트림 오류로 완료하지 못했다.
- [민지 환영 화면](../artifacts/unity-overnight/guide/welcome.png) · [최신 4명 자동 시연](../artifacts/unity-overnight/four-patient/visit.mp4). 파일별 시험 조건과 배속은 각 단계 기록을 참고한다. 6명 및 연구 영상은 각각의 달성 상태에서 시작한 별도 시연으로, 한 번의 수동 플레이에서 전부 달성한 영상을 의미하지 않는다.

### 남은 확인과 재개 지점

다음 세션에서는 Mac 개발 빌드에서 안내를 닫고 **환자 선택 → 접수 → 계획 지시 → 저장 후 재실행**을 수동으로 확인한다. 이어 같은 빌드의 좁은 가로 창 및 실제 모바일에서 HUD 터치 영역과 장비 승하차 간섭을 본다. Godot의 전체 스토리·챕터 연출은 이 운영 흐름 이식 이후의 대상이다. Android Build Support 및 SDK·NDK·JDK, iOS Build Support는 설치를 확인하지 못했다. Xcode 전체 도구와 iOS 기기 서명도 이 작업에서 하지 않았다. Mac에서 확인한 결과를 모바일 성능으로 해석하지 않는다.

### 임시 설계

평판은 시즌 기획의 시작값 10과 챕터 1–4의 각 3점을 사용한다. 현재 시뮬레이션에는 영업시간·만족도·진료품질 평가가 없으므로 본원 마감마다 1점을 올린다. 자동 시나리오에서는 18일차 마감에 조건을 충족해 19일차에 개원했다. 분원 도착 간격 3초, 운영일 경계 개원, 개원 시 기본 위임은 이 범위의 임시 정책이다. 공동 자금에서 설립비 9,000만을 지불하고 두 병원 수입을 합산한다. 각 병원의 설비·연구 구입은 현지 장부와 공동 자금 양쪽이 구매를 감당해야 한다. 분원의 초기 내부 장부 900만은 공동 자금을 늘리지 않는다. 분원 예약은 별관 설치 후에도 4명으로 유지한다. 정식 지역별 수요 지표, 챕터 보상과 해외 콘텐츠는 구현 대기다.
