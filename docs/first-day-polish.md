# 첫날 플레이의 완성도 개선

기준은 `6878018`의 `story-welcome-1x.mp4`, `story-completion-1x.mp4`, `story-ending-1x.mp4`다. 원본 영상과 검사 기록은 보존한다. 이번 결과는 [실제 엔진 영상과 캡처](first-day-polish.html)에서 확인한다.

## 직접 행동으로 이어지는 첫 방문

민지의 첫 인사 한 줄과 김영수의 긴장한 첫 방문 한 줄 다음에 환자 선택과 접수를 진행한다. 이전의 별도 접수 설명 대화는 없애고 실제 접수 버튼 위의 짧은 문구와 민트 테두리로 안내한다. 선택은 접수를 대신하지 않는다. 접수·계획을 먼저 실행한 경우 같은 행동을 다시 요구하지 않는다.

CT·계획·치료 안내는 실제 상태에서 한 번씩 표시한다. 읽는 중인 대사는 시간 경과나 다른 환자의 진행으로 자동 종료되지 않는다. 다음/이번 대화 건너뛰기 또는 관련 행동의 실제 실행으로 진행한다. 대사에 읽기 제한이나 자동 넘김 타이머는 없다. 카메라 방향·환자 모션·장비 예약은 유지한다.

## 대화와 안내 설정

- 이름 → 본문 → 민트색 ‘다음’의 우선순위를 분명히 했다. ‘이번 대화 건너뛰기’는 보조 텍스트 버튼이다.
- ‘안내 설정’은 왼쪽 아래의 별도 경로다. 설정 안에서 안내를 끄거나 다시 켤 수 있다. 저장 복원 후에도 선택을 유지한다.
- 다시 켜면 현재 할 일의 짧은 안내부터 시작한다. 과거 인사·검사·감사 대사를 한꺼번에 재생하지 않는다. 아직 발생하지 않은 완료/증축/첫날 종료는 이후 실제 상태에 연결된다.
- 844×390에서 본문 약 16.6px, 이름 약 17.3px, 새 대화·설정 및 주요 행동 버튼의 터치 높이 최소 44px를 확인한다. 전체 패널을 화면 전체로 늘리지 않는다. 환자 카드와 대기/계획/CT 인물의 얼굴 가림도 실제 투영 좌표로 검사한다.

## 실제 구매에 연결한 별관 완공

병원 밖의 실제 부지에 낮은 대비의 채움·테두리·읽기 쉬운 안내를 표시한다. 부지를 클릭하면 기존 600만 확인창이 열린다. 확인창은 부지가 보이는 왼쪽에 놓고 ‘치료실 1개 추가 / 최대 두 환자 동시 치료’를 명시한다. 취소는 비용·시설·장부를 바꾸지 않는다.

기존 `purchase_expansion()` 성공 분기에서만 비용을 차감하고 시설을 추가한다. 1.6초의 작은 반짝임과 부지 강조, ‘치료실이 하나 늘었어요’와 민지의 짧은 반응을 연결한다. 건물은 구매 즉시 완공·운영 가능한 모습이다. 시각 연출을 위해 운영을 지연시키거나 건물을 숨기지 않는다. 유료 대기·건설 타이머·추가 재화는 없다.

구매는 카메라 이동이나 확대를 일으키지 않는다. 확장된 저장을 처음 불러오면 별관을 포함한 기본 운영 구도를 잡는다. 사용자가 병원 안으로 돌아오면 새 치료실 테두리와 ‘운영 중’ 표시가 3.5초간 나타난다. 직접 안팎 전환에 따른 기존 전체 구도는 유지한다. 구매 직후 즉시 저장하며, 연출 도중 불러오면 완공된 시설을 표시하고 구매 효과를 재생하지 않는다. 짧은 입자 연출의 재생 위치는 저장하지 않는다.

## 오늘의 병원 일지와 실제 기록

네 환자가 모두 실제 귀가한 뒤 날짜(현재 게임의 운영일), 완료 인원, 진료 수입, 증축 지출, 현재 자금, 오늘 추가된 시설을 보여준다. 첫날에는 민지의 짧은 마무리 문구와 체크 표시를 사용한다. 2일차 이후의 문구는 첫날과 다르다. 결과를 보는 강제 대기 시간 없이 다음 날로 넘어가거나 일지를 닫고 병원을 둘러볼 수 있다. 하단 일지 버튼으로 다시 열 수 있다.

`daily_ledger.gd`는 기존 정산과 구매 성공 지점에서만 영수증을 기록한다. 일지를 열거나 닫거나 불러오는 동작은 수입을 지급하지 않는다. 첫날 수입 800만과 보유 자금을 구분한다.

| 첫날 선택 | 시작 자금 | 진료 수입 | 증축 지출 | 현재 자금 | 새 시설 |
| --- | ---: | ---: | ---: | ---: | --- |
| 증축 | 900만 | 800만 | 600만 | 1100만 | 치료별관 |
| 증축 보류 | 900만 | 800만 | 0 | 1700만 | 없음 |

다음 날은 실제 남은 자금을 시작 잔액으로 기록하고 수입·지출·새 시설 표시만 초기화한다. 자금·별관은 유지한다. 연속 다음 날 요청은 기존 `all_done()` 조건으로 한 번만 실행된다.

저장은 기존 v2에 선택적인 `daily_ledger` 필드를 추가한다. 이전 저장에 장부가 없으면 기존 환자별 `paid` 기록에서 확인 가능한 현재 진료 수입만 복원한다. 시작 잔액·과거 증축 지출·새 시설 이력은 추측하지 않고 ‘기록 없음 · 이전 저장’으로 표시한다. 다음 날부터는 완전한 기록을 시작한다. 해석할 수 없는 장부는 게임 상태를 일부 적용하지 않고 기존 저장 보호 정책으로 원본을 보존한다.

## 변경 파일

- `godot/scripts/first_day_story.gd`: 짧은 시작 대화, 읽기 보존, 상태에 맞춘 안내 다시 켜기.
- `godot/scripts/main.gd`: 대화/설정 배치, 실제 버튼 안내, 부지 선택, 구매 성공 연결, 일지 표시.
- `godot/scripts/daily_ledger.gd`, `hospital_simulation.gd`: 실제 거래 기록, 새 날 초기화, 이전 저장 호환·검증.
- `godot/scripts/day_journal.gd`: 현재 운영 기록으로 그리는 병원 일지.
- `godot/scripts/world.gd`: 같은 부지의 선택 표시, 구매 후 반짝임, 내부 새 치료실 강조. 캐릭터·장비 메시와 이동 경로는 변경하지 않았다.
- `godot/tests/test_first_day_polish.gd`, `test_story.gd`, `test_story_ui.gd`, `test_scene.gd`: 거래/저장/설정/입력/카메라 회귀.
- `godot/tests/record_first_day_polish.gd`, `tools/run-visual-qa.py`: 세 구간의 실제 엔진 자동 입력 녹화.

## 검증과 전달

구현 기준 커밋은 `a4af74fb5f1e93f4546e30ed7d38d6d846469df6`이며, 운영 51·모션 48·이야기 84·장부/복원 70·기존 화면 172·개선 UI 271로 총 696개 검사를 통과했다. 데스크톱 Chromium 클릭과 844×390 터치 에뮬레이션에서도 실제 접수와 환자·이야기·일지 데이터의 IndexedDB 저장을 통과했다. 최종 검사 결과·해시·영상 메타데이터는 [검증 기록](first-day-polish-results.json)에 보관한다. 영상은 정상 1배속의 실제 Godot 화면이며 입력만 자동화했다. 수동 플레이로 표시하지 않는다. 첫 영상은 새 게임부터, 증축과 일지 영상은 정상 공개 운영 동작으로 준비한 체크포인트에서 시작한다. 체크포인트 이후 게임 시간을 빠르게 돌리거나 치료 상태를 덮어쓰지 않는다. 병원 밖에서는 기존 정책대로 운영이 정지한다.

검사는 Linux Godot 4.6.3 Compatibility/Mesa llvmpipe 및 Chromium 소프트웨어 WebGL 기준이다. 터치 에뮬레이션과 실제 iPhone/Safari 성능은 구분한다. Mac/iPhone 실기기 성능·발열·터치 감각은 확인하지 않았다. 기존 초상·부위 피벗 모션을 사용하며 음성·입 모양·완전한 건설 공정 애니메이션은 없다. 일지는 현재 운영일의 기록이며 과거 일지 보관함은 없다. 미구현 연구·지도·결제나 추가 결산 보상은 제시하지 않는다.

기획 원문의 챕터 보상·평판·운영비·재방문 안내는 이번에도 적용하지 않는다. 최신 요청대로 900/200/600만 경제와 실제 운영 범위를 유지한다.

새 첫 인사 영상의 접수 입력은 약 9.04초이며, 이전 영상은 약 20.46초였다. 자동 입력의 대사 읽기 타이밍도 다르므로 실제 유저의 속도 측정이나 동일 조건 벤치마크로 해석하지 않는다. 게임 자체에는 읽기 시간 제한이 없다. 재현 명령은 `./tools/test-godot.sh`, `python3 tools/run-visual-qa.py --story-check`, `python3 tools/run-visual-qa.py --movie --polish welcome --output-dir artifacts/review-welcome`이며 `expansion`, `journal`도 같은 방식이다.
