# 작업 재개 상태 · 2026-11-04

## 확보한 자료

추가로 받은 첫 시즌 상세 기획 v1.0과 수익화 제안은 `reference/`에 원문 그대로 보관했다. [제작 기준 메모](design-baseline.md)에 적용 기준·가로/세로 충돌·다음 작업 순서를 기록하고 AGENTS.md에서 다음 작업자가 확인하도록 연결했다. 연구소·분원·상점 등 기획된 기능을 새로 구현한 것은 아니다.

현재 checkout에서 이전 Godot 소스와 ZIP은 발견되지 않았다. 원격에는 초기 README 커밋만 있었다. 사용자 인계서 및 이전 첨부 식별자로 원본 기획서와 HTML을 실제 다운로드해 `reference/`에 보존했다. 과거 환경 자체를 복구하거나 이전 코드와 바이트 단위로 동일하게 복원한 것은 아니다.

## 이번 재구현

- 화면과 독립된 운영 시뮬레이션, waypoint를 따른 이동, 장비 이동 예약 및 FIFO 대기열.
- 대기·CT·계획·치료실과 실제 3D 장비, 직원, 환자, 기본 보행과 눕기.
- 오늘의 환자 4명 목록, 도착 예정·선택·접수/계획 필요·대기 순서 표시.
- 명시적인 조작 필요 환자 이동 버튼. 상태 갱신으로 선택을 강제로 바꾸지 않음.
- 첫 치료 후 600만 증축 확인·취소, 실제 별관·두 번째 장비·동시 치료.
- 안팎 전환 시 일시정지와 이전 재생 상태 복원.
- 치료 완료 시 200만 1회 지급, 귀가 후 다음 날, 자금·별관·누적 인원 유지.
- 검증 후 원자적 로컬 저장, 복원 시 일시정지, 손상되거나 다른 구현의 저장 파일 보존.

## 이전 기록과 다른 범위

이전 55개 테스트 및 영상은 현재 실행 결과가 아니다. 이번 테스트와 화면은 별도 기록한다. 인계서에 있던 `simulation.gd`와 v1 이전 로직은 원본을 확보하지 못해 재현하지 않았다. 현재 저장은 `implementation: sunshine-rebuild-2026-11` 표식을 가진 v2 JSON만 읽는다. 이전 저장은 호환 검토 전에 덮어쓰거나 자동 이전하지 않는다. 원래 v1 파일이 있으면 자동 저장도 중단하고 안내한다.

3D 외관은 운영용 기본 도형이다. 자유 건축, 최종 아트·리깅, 스토리, 수동 계획 퍼즐, 여러 날 치료 과정, 직원 채용/자동 운영, 장기 경제·평판, 지도·연구소, 음악·결제·계정, 모바일 빌드와 스토어 배포는 미구현이다.

## 파일 보관

소스·원본 참고 문서·선택한 실제 엔진 캡처를 커밋한다. 원격 푸시 뒤 원격 main SHA와 로컬 SHA를 비교한다. 푸시 성공이 새 cloud task의 스냅샷 복원 검증을 의미하지는 않는다. 클라우드 설정 저장과 환경 publication 역시 별개이다.

## 사용자 참고 이미지에 따른 첫 아트 개선

사용자가 내부·외관·연구소가 함께 있는 시각 기준을 제시했다. [아트 기준](art-direction.md)에 특징과 남은 차이를 기록했다. 나무 마감·코랄 의자·유리창·실내 소품·둥근 가구·인물·장비 외장을 적용했고 외관과 조명을 조정했다. 초기 형태 표현을 발전시킨 단계이며 참고 이미지 수준의 최종 아트 완성으로 취급하지 않는다.

## 전체 화면과 게임 UI

상단 문서형 제목 영역과 항상 보이는 환자 목록·하단 패널을 없애고 3D 공간을 창 전체에 배치했다. 기본 카메라는 접수실과 CT를 가까이 보여 준다. 드래그로 이동하고 확대·축소·전체 보기로 살펴본다. 세로 화면에서 병원 전체를 한 번에 보려면 전체 보기 버튼을 사용한다.

자금·일차·진료 수·정지·배속은 크림색 상단 HUD에 표시한다. 하단 가운데에는 병원 전체·환자·진료 지시·증축, 왼쪽에는 안팎 전환과 확대·축소를 둔다. 환자 목록은 요청할 때 열리고 선택한 환자의 초상화·진료 단계·행동을 오른쪽 패널로 표시한다. 증축 확인은 게임 안의 모달이며 배경 입력을 차단한다. 창 비율에 따라 3D 영역을 확장한다. 모델·재질 자체의 후속 아트 개선은 별도 작업이다.

## 가로 화면과 대표 장면 · 2026-11-04

사용자가 가로 화면 기준 제작을 승인했다. 논리 화면은 960×540이며 기본 창과 전달 영상은 1280×720이다. Mac과 아이폰 가로 비율에 맞춰 3D 영역을 확장하고, 세로 접속에는 가로 전환 안내를 표시한다. 웹에서 기기 회전을 강제로 잠근다고 주장하지 않는다.

운영 아이콘은 하단 가운데, 안팎 전환·확대·축소는 왼쪽 아래에 모았다. 환자 행동은 오른쪽의 작은 패널로 열리며, 기본 카메라에서 접수·CT·계획·치료실을 함께 본다. 환자 선택 시 카메라가 주변 공간을 함께 보여 주도록 이동 범위를 조절했다.

대표 장면은 밝은 목재 접수대, 두툼한 코랄 의자, 열린 구멍과 넓은 전면을 가진 CT 외장, 따뜻한 벽등·스탠드, 액자·책·찻잔, 창 밖 화단과 나무를 갖춘다. 대기·CT 대기 환자는 실제 의자에 앉으며 첫 환자는 책을 읽는다. 접수하면 서서 기존 동선으로 이동한다. 시뮬레이션의 위치·저장 형식·운영 수치는 유지한다. 최종 리깅과 참고 이미지 수준의 재질 완성은 후속 작업이다.

## 별도 3D 에셋으로 내부 교체

병원 내부·치료 별관·환자·간호사를 Blender에서 제작한 GLB로 교체했다. `art/source/`에 패킹된 Blender 원본, `tools/art/`에 제작·내보내기·검사 코드를 보관한다. 곡선 가구와 장비, 복도 벽·열린 문틀, 원본 목재·직물 패턴, 구운 접촉 음영, 캐릭터 관절과 얼굴을 적용했다. 인물은 부위별 묶음과 별도 앉은 자세를 사용하며 최종 스킨 리깅은 아니다. 외관은 기존 모델이다. 현재 아트와 남은 차이는 [아트 방향](art-direction.md)을 기준으로 본다.

## 최신 아트·UI 개선

[동일 카메라 전후 비교](art-review.html)와 [제작·환경 기록](art-review.md)을 보관한다. 연속 바닥과 낮은 대비의 경계, 정돈된 코랄 쿠션·접수대·CT, 별도 회전부와 헤드의 치료기, 약 2.7등신의 단발 민지를 적용했다. 기본색·거칠기·AO·반사·주광을 분리하고 셀프 그림자 오류를 조정했다. 미세 소품부터 감량해 주요 곡면을 보호하며, 가구별 편집 파트를 Blender 원본에 보존한다. 게임 UI도 사용자가 추가한 크림·청록 시안을 기준으로 바꿨다. 3D 렌더는 HUD의 논리 해상도와 분리해 최대 1280×720이며 입력 좌표를 변환한다. 실제 Mac/iPhone 성능 및 공개 Pages 접속은 미확인이다.

## 플레이 구도·피드백 개선

최신 [플레이 검토](play-feedback.html)에서 UI 가림을 피하는 구도, 대기 이유·차례·자동 진행 안내, 짧은 말풍선, 소재별 반응과 치료 자세를 확인한다. 본원·별관 치료기와 환자가 같은 -35° 방향을 사용하며 몸통·베개·헤드 간격과 얼굴의 시선 가림을 검사한다. 운영 규칙과 저장 형식은 그대로다. 직접 드래그·줌은 자동 구도보다 우선하고 재선택/전체 보기로 자동 구도를 복원한다.

## 안정적인 기본 카메라 · 2026-11-05 KST

[최신 카메라 검토](stable-camera.html)에서는 기본 병원 크기를 키우고 단계별 자동 확대를 제거했다. 카드 열기는 현재 확대율을 유지하고, 화면 밖 환자만 최소 이동으로 찾는다. ‘환자 보기’ 버튼은 상세 확대, ‘병원’ 버튼은 기본 시점 복귀다. 전환은 0.42초이며 드래그·줌으로 중단한다. 상태 안내·치료 자세·경제·시설·저장은 이전 버전 그대로 유지한다.
