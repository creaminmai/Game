# 민지 — 12각도 참고와 연결부 제작 기준

2026-11-23 KST. [12각도 PNG](../reference/art/minji-simple-12views/minji-12-view-sheet.png)를 **직접 열어서** 보고 현재 진행 중인 민지 수정에 반영한다. 이전 상세 인간형 얼굴로 돌아가거나 기존 작업을 처음부터 폐기하지 않는다. 이 문서는 최신 사용자의 둥근 입체감·뽀얀 피부·자연스러운 연결부·얇은 꽃 배지 요청을 통합한다.

## 형태와 표면

- 큰 둥근 머리, 짧고 작은 몸, 갈색 단발, 타원 눈과 작은 미소, 민트 근무복을 유지한다. 정면뿐 아니라 측면에서 이마·볼·턱·뒤통수가 둥근 덩어리로 이어지고, 가슴과 등 모두 깊이가 있는 둥근 몸통이어야 한다. 이미 늘린 깊이를 무조건 더 늘리지 말고 실제 실루엣을 비교한다.
- 몸통→어깨→소매를 연속적인 옷 표면으로 만든다. 끼워 넣은 어깨 캡, 틈, 겹친 내부 면을 제거한다. 오브젝트 Join이나 Shade Smooth만으로 연결했다고 판단하지 않는다. 필요 부위의 메시를 실제로 연결하고 곡률과 노멀을 정리한다. 소매 끝과 피부의 실제 의복 경계는 남긴다.
- 팔→손목→장갑형 손→작은 엄지를 부드럽게 연결한다. 손목 고리와 붙인 구슬 같은 엄지 뿌리를 없앤다. 관절별 별도 오브젝트 회전 때문에 벌어지면 해당 부위를 스킨 메시와 본·웨이트로 바꾸고, 기존 Transform 애니메이션이 중복 적용되지 않게 한다.
- 볼터치는 피부의 색으로 표현한다. 돌출 타원 판과 그 테두리·그림자를 없앤다. 코는 작고 둥근 삼각형을 유지하며 뿌리가 얼굴로 부드럽게 이어지게 한다. 귀 뿌리도 정리하되 눈과 입의 단순하고 또렷한 그래픽은 유지한다.
- 피부는 얼굴과 손에 같은 뽀얀 복숭아색을 사용한다. 기존 #F5D5C5를 출발점으로 중립광과 실제 병원 조명을 비교한다. 누런 조명·색 관리·짙은 접촉 그림자를 분리해 확인하고 피부 전체 발광이나 그림자 전부 제거로 해결하지 않는다.

## 꽃과 작은 장식

- 해바라기 중심은 얇고 가장자리가 둥근 갈색 원판, 꽃잎은 구슬 대신 납작한 물방울 모양으로 만든다. 뿌리는 중심 아래에 들어가며 꽃잎마다 깊은 검은 틈이 생기지 않아야 한다.
- 전체 배지 두께는 지름의 약 10~15%를 시작 기준으로 실제 카메라에서 조정한다. 가슴 곡면에 밀착시키고 뜨거나 옷에 파묻히지 않게 한다.
- 꽃과 명찰을 분리해 배치해 관통을 없앤다. 꽃 아래 갈색 돌기가 의도된 연결 부품이 아니라면 제거한다. 단추·주머니·명찰도 불필요한 두께와 뜬 부분을 정리한다.
- 실제 액세서리와 의복 경계는 유지한다. 모든 물체를 하나로 용접하거나 모든 경계를 흐리게 하는 작업이 아니다.

## 실제 모델로 검수

1. Blender의 외곽선·cavity 효과를 끈 화면, 중립광 렌더, Unity 대화·운영 화면을 비교해 실제 틈과 뷰포트 효과를 구분한다.
2. 같은 모델·포즈·재질·배율로 12칸 비교 시트를 만든다: 정면, 앞왼쪽 45도, 정확한 왼쪽 측면, 뒤왼쪽 45도, 후면, 뒤오른쪽 45도, 정확한 오른쪽 측면, 앞오른쪽 45도, 높은 정면, 높은 앞왼쪽, 낮은 정면, 높은 뒤오른쪽. 높은 시점은 약 40~45도, 낮은 시점은 약 25도로 시작하며 실제 카메라 값을 기록한다.
3. 참고 이미지의 각도 표기는 엄밀하지 않다. 배지의 신체 기준 왼쪽 위치, 앞머리 방향, 정면 기준 비율을 고정하고 실제 카메라를 회전한다. 참고에 있는 불일치를 복제하지 않는다.
4. 팔 45도·90도, 인사 최고점·내리는 구간, 보행에서 어깨·손목의 틈과 찌그러짐을 확인한다. 위에서 꽃 배지, 아래에서 턱·소매·손목을 확대 확인한다.
5. 실제 Unity 운영 화면 크기에서 꽃이 해바라기로 읽히고 피부·얼굴이 보이는지 확인한다. 생성 PNG를 게임 캐릭터나 실제 구현 결과로 사용하지 않는다.

## 결과물과 범위

편집 가능한 .blend, Unity용 모델, 같은 카메라 수정 전후 비교, 실제 모델 12각도 시트, 정상 속도 인사·보행 영상, 남은 차이를 기록한다. 로직 테스트 통과 수를 외형 완성도의 근거로 삼지 않는다. 기존 모델·사용자 저장·게임 규칙을 보존한다. 현 작업의 검토 브랜치에 변경을 커밋하고 푸시 성공과 원격 SHA를 확인한 경우에만 업로드 완료라고 보고한다.
