## 한계

Xorg dummy 드라이버는 V-Sync 변경을 지원하지 않는다는 경고를 출력했다. 렌더링과 입력·기능 검증은 완료됐으며 이 경고를 모바일 성능 결과로 해석하지 않는다. 제한된 셸에서는 엔진 editor의 로컬 TCP 포트 생성이 차단될 수 있으며, 그래픽 QA는 로컬 소켓 생성이 허용된 실행에서 수행했다.

## 참고 이미지에 따른 아트 개선 후 재검증

둥근 메시·캐릭터 비율·가구·의료 장비·유리창·복도 마감·건물 외형·조명을 변경한 뒤 운영 테스트 **51개**, 실제 UI 입력 및 장면 검사 **40개**가 모두 다시 통과했다. 이번 그래픽 QA 결과는 `artifacts/art-direction/`에 기록했다. 치료 중 캐릭터가 새 매트리스에 묻히지 않도록 누운 위치를 보정하고 실제 동시 치료 캡처를 확인했다.

## 영상·웹 체험 전달 검사

공식 Godot 4.6.3 내보내기 템플릿의 전체 SHA-512를 릴리스 체크섬과 비교했다. 단일 스레드 웹 빌드를 검사한다. 실제 캔버스에서 환자 아이콘 → 목록 선택 → 상황별 접수 버튼을 누르고 IndexedDB에 `walk_ct` 상태가 저장되는지 확인한다. 소프트웨어 WebGL의 화면 갱신과 비동기 저장 완료를 기다리도록 검사 코드를 조정했다. 창을 채우는 캔버스와 Godot의 확장된 논리 좌표를 사용한다. 데스크톱 Chromium과 390×844 터치 에뮬레이션 모두 통과했다. 실제 Safari/iPhone 검증은 별도이다.

증축 확인창을 게임 안의 Control 모달로 변경했다. `--movie --input-check`에서 실제 입력으로 접수·증축 확인·병원 내부 복귀를 통과했다. 실패한 시연은 전달용 MP4로 변환하지 않는다. 전체 시연의 완료·금액·동시 치료·다음 날 결과도 통과해야 MP4를 만든다.

최종 MP4: 55.04초, H.264, 540×960, 24fps, 1,142,684바이트, 무음. 전체 영상 디코딩 검사를 통과했다. 자동 시연(진료 4배속)으로 환자 4명 진료·귀가, 별관 증축, 동시 치료 2명, 자금 1100만, 다음 날 2일차까지 완료했다. 전체 화면과 선택 환자의 가까운 모습, 증축 확인, 전체 보기에서 두 치료실 운영을 담았다. 상세 결과는 `docs/media/playthrough-results.json`에 보관한다. 24fps 인코딩은 모바일 실행 성능 결과가 아니다.
