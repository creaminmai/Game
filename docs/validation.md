## 상세 아트와 게임 HUD 개선

대표 장면과 접수대 확대의 수정 전후를 고정 카메라로 촬영했다. [비교 페이지](art-review.html)는 실제 PNG를 겹쳐 비교하며 합성된 게임 배경이나 가짜 플레이 화면이 아니다. 새 UI의 1/2배속·환자 단계·초상화·진료 버튼을 실제 운영 상태에 연결했다. 1280×720 창에서 논리 HUD는 960×540을 유지하면서 실제 3D 렌더는 1280×720이 되는지, 선택 패널이 화면에 맞는지 검사했다. 환자 4명 귀가·동시 치료 2명·자금 1100만·다음 날을 재확인했다.

Blender 원본은 가구별 편집 컬렉션과 검토 카메라/조명을 포함한다. 주요 곡면은 보호하고 작은 반복 부품을 베이크 전에 감량한다. 기본색·AO 색 공간, 두 UV 채널, 피부 정점 음영, 출입구 최종 메시 검사를 유지한다. 그림자 투영과 정밀도·바이어스를 조정하고 깨끗한 기본색/미세 패턴과 중립 환경 반사를 사용한다. 렌더링 환경과 남은 시안 차이는 [아트 검토](art-review.md)에 기록한다.

이전 `3119d2f`의 네이티브·웹·터치·영상 결과와 Blender 원본 감사 결과의 전달용 사본은 [검사 결과 JSON](art-review-results.json)에 보관한다. 영상은 H.264/BT.709로 인코딩했으며 8·16·25·32초 프레임에서 CT 사용, 외관 전환, 증축 후 두 치료실, 완료 상태를 육안 검토했다. 실제 Safari/iPhone과 공개 Pages 접속은 이 결과에 포함되지 않는다.

## 이전 5e60676의 플레이 구도·피드백 회귀 검사

최종 네이티브 검사 158개에는 CT 상단과 선택 환자·장비의 투영 좌표가 실제 HUD와 카드 바깥에 위치하는지, 창 크기 변경 후에도 가로 구도가 유지되는지 검사가 포함된다. 직접 드래그·줌, 실제 3D 클릭, 환자 목록·지시·증축 취소/확정·동시 치료·다음 날을 다시 실행했다. 4명 귀가, 자금 1100만, 두 치료실 동시 사용과 복원 가능한 저장을 재확인했다.

CT 대기 안내는 실제 앞 환자가 장비로 이동 중인 상황에서 검사했다. 치료 대기 안내와 자동 진행 문구도 확인했다. 대기 카드 제목이 두 줄에 들어가는지, 치료 대기 환자와 사용 중인 장비가 하단 메뉴에 가려지지 않는지 검사했다. 장비·목재·천이 서로 다른 가져오기 재질 값을 사용하는지도 확인했다.

실제 캐릭터 메시를 침대 좌표로 변환한 몸통 뒷면은 높이 1.08, 머리 뒷면은 약 1.213이다. 매트리스 상면 1.085, 베개 상면 1.21과 비교한다. 몸통 윗면 약 1.508과 치료 헤드 하단 1.6875 사이 약 0.179의 간격, 침대 길이 범위도 검사했다. 두 치료실에서는 카메라에서 얼굴까지 실제 장비의 삼각형으로 광선 검사를 실행해 시선을 가리지 않음을 확인했다. 이는 모든 애니메이션 프레임의 정밀 충돌 검사를 뜻하지 않는다.

현재 전달 결과와 영상 메타데이터는 `play-feedback-results.json`에 기록한다. 이전 영상·검사 결과를 최신 결과로 덮어쓰지 않고 구분한다.

정상 1배속 영상은 54.041667초의 1280×720/24fps H.264 파일이다. 실제 캔버스 클릭 17회로 환자 직접 선택 2회, 접수 2회, 계획 지시 2회를 수행했다. 게임 처리 1,296프레임에 대응하는 시뮬레이션 시간은 53.991667초이며 1배속을 유지한다. 입력은 자동화했으며 수동 플레이 영상으로 표시하지 않는다. 9·15·28·45·50초 프레임에서 지시·대기·치료와 마지막 대기 구도를 확인했다.

최신 전체 운영 영상은 34.791667초, 1,850,903바이트의 자동 입력·진료 6배속 시연이다. 네 환자 완료, 자금 1100만, 별관 증축, 두 명 동시 치료와 2일차 시작을 통과했다. 8·16·25·32초 프레임에서 CT 대기 안내, 외관 전환, 두 치료실 가동과 완료 상태를 확인했다.
