## 영상·웹 체험 전달 검사

공식 Godot 4.6.3 내보내기 템플릿의 전체 SHA-512를 릴리스 체크섬과 비교했다. 단일 스레드 웹 빌드를 만들었다. 실제 캔버스에서 환자 아이콘 → 목록 선택 → 상황별 접수 버튼을 누르고 IndexedDB에 `walk_ct` 상태가 저장되는지 확인한다. 소프트웨어 WebGL의 실제 프레임과 비동기 저장 완료를 기다린다. IndexedDB를 직접 읽어 첫 환자의 도착을 확인한 뒤 조작하고, 접수 이후 상태를 다시 읽어 검사한다. JS Promise 핸들 자체를 저장 성공으로 취급하지 않는다. 중간 화면 네 장을 매번 캡처하지 않고 최종 조작 결과를 캡처하며, 필요한 경우 `--debug-captures`로 단계별 이미지를 남긴다. 창을 채우는 캔버스와 Godot의 확장된 논리 좌표를 사용한다. 데스크톱 Chromium과 844×390 가로 터치 에뮬레이션 모두 통과했다. 실제 Safari/iPhone 검증은 별도이다.

증축 확인창을 게임 안의 Control 모달로 변경했다. `--movie --input-check`에서 실제 입력으로 접수·증축 확인·병원 내부 복귀를 통과했다. 실패한 시연은 전달용 MP4로 변환하지 않는다. 전체 시연의 완료·금액·동시 치료·다음 날 결과도 통과해야 MP4를 만든다.

최종 MP4: 55.04초, H.264, 1280×720, 24fps, 2,253,401바이트, 무음. 전체 영상 디코딩 검사를 통과했다. 자동 시연(진료 4배속)으로 환자 4명 진료·귀가, 별관 증축, 동시 치료 2명, 자금 1100만, 다음 날 2일차까지 완료했다. 별도 모델과 구운 접촉 음영을 적용한 병원에서 대기·CT 장면, 증축 확인, 전체 보기의 두 치료실 운영을 담았다. 상세 결과는 `docs/media/playthrough-results.json`에 보관한다. 24fps 인코딩은 모바일 실행 성능 결과가 아니다.

## 별도 Blender/GLB 에셋 검사

`python3 tools/art/check_assets.py`는 네 GLB의 컨테이너 길이, 패킹된 텍스처, 두 UV 채널 제한, 정적 모델 AO 연결, 캐릭터 정점 음영·필수 피벗·부위별 묶음과 삼각형 예산을 확인한다. `./tools/test-godot.sh`에서도 이 검사를 실행한다.

- 병원 내부: 300,000 삼각형 / 26 재질 표면.
- 치료 별관: 32,456 삼각형 / 17 표면.
- 환자: 51,396 삼각형 / 29 표면, 독립 포즈 부품 9개.
- 간호사: 53,212 삼각형 / 30 표면, 독립 포즈 부품 9개.

Blender의 부모 피벗 적용 순서와 세 번째 UV 레이어 생성 문제를 실제 캡처에서 발견해 수정했다. Godot 4.6.3가 가져온 AO 재질이 UV0을 사용하던 문제도 후처리로 보정했다. 이를 GLB 검사와 실제 엔진의 신체 범위·재질 검사로 재발 방지한다. 128샘플 AO와 조명을 조정한 뒤 같은 카메라에서 실제 게임 렌더를 육안 검토했다. 경로와 시뮬레이션 규칙·저장 형식은 그대로 사용한다.

웹 패키지에서는 중간 베이크 PNG와 에디터 전용 후처리 스크립트를 제외하고 연결된 게임 리소스를 내보낸다. `.blend` 원본은 프로젝트 바깥 `art/source/`에 있으며 웹 배포에 포함하지 않는다.

계획실의 기존 출입 경로(z=-1)에 맞춰 문을 배치했다. Blender 내보내기 단계에서 감량된 최종 메시의 네 출입구에 높이와 옆 간격을 달리한 36개 광선을 쏴 실제로 벽·문틀이 길을 막는지 검사한다. 단순한 시뮬레이션 완료 검사로는 잡지 못하는 시각적 관통을 별도로 확인한다.
