# 플레이 구도·상태 피드백 개선

이 문서는 `5e60676` 버전의 기록이다. 이후 기본 카메라를 안정화한 최신 결과는 [카메라 검토](stable-camera.md)에서 확인한다.

기준 버전은 `3119d2f`와 기존 `docs/media/playthrough.mp4`다. 기존 환자 카드·목록·FIFO 대기열·증축·동시 치료·다음 날·저장 규칙을 보존하고, 화면을 읽고 지시하는 경험을 다듬었다.

## 구도

카메라가 화면 전체 대신 상단 HUD·목표창, 하단 조작부와 열린 오른쪽 카드/목록을 제외한 영역을 사용한다. 기본 화면은 접수·CT 중심이다. 환자를 선택하면 해당 환자와 검사·치료 장비가 함께 들어오는 구도를 계산한다. 이동 중에는 출발 공간과 목적 공간을 포함하고, 도착하면 해당 진료실을 보여 준다. 치료 대기에서는 대기 환자와 사용 중인 치료기를 함께 보여 준다. 안팎 전환 뒤에도 선택 환자의 구도를 복원한다.

직접 드래그·줌을 하면 자동 구도 조정을 잠시 해제한다. 환자를 다시 선택하거나 병원 전체 보기를 누르면 자동 구도로 돌아온다. 사용자의 시점 조작을 상태 갱신이 반복해서 덮어쓰지 않는다. 세로 화면은 기존 가로 전환 안내를 유지한다.

## 안내

실내에 떠 있던 방 이름과 고정 조작 설명을 제거했다. 접수나 계획 지시가 필요한 환자에게만 짧은 말풍선을 표시한다. 선택 환자를 우선하고, 없으면 다음 조작 대상 한 명을 표시해 말풍선이 서로 겹치지 않게 한다. 자세한 이유는 오른쪽 카드에 둔다. 구매·취소·다음 날 알림은 4초 뒤 사라진다.

카드의 버튼과 설명은 실제 상태를 구분한다. CT 대기는 차례, 앞에서 대기하는 인원, 앞 환자의 장비 이동/이용 상태, 추가 지시 없이 자동 진행되는지를 알린다. 계획·치료 대기도 대기 대상으로 표시한다. 이동, 검사·검토·치료 중, 지시 필요, 귀가를 같은 문장으로 뭉뚱그리지 않는다. `patient_feedback.gd`는 표시만 담당하며 예약·배정·경제·저장 형식을 변경하지 않는다.

## 재질과 빛

노출과 화면 전체 채도는 유지했다. 중립 환경광을 0.62→0.43, 따뜻한 주광을 0.10→0.14, 보조광을 0.04→0.055로 분리해 조정했다. 주광 그림자 불투명도는 0.48, 필터 블러는 3.0이다. 강한 그림자 경계를 약하게 하면서 기존 접촉 AO는 유지한다.

Godot의 `import_hospital.gd`에서 목재·직물의 기본색 반응을 각각 보정한다. 코팅 외장은 거칠기 0.26/반사 0.50, 목재는 0.46/0.35, 직물은 0.82/0.22를 사용한다. 반사는 Godot의 비금속 specular 값이며 금속성을 추가한 것이 아니다. Blender 원본의 기본색과 텍스처는 보존하고, 엔진 조명 아래의 최종 보정을 명시적으로 분리했다. 같은 카메라의 실제 엔진 캡처로 비교한다.

## 치료 자세

본원·별관 치료기와 침대를 Blender에서 각각 -35° 회전했다. 편집용 파트와 게임 메시·커스텀 노멀을 함께 돌리고 AO를 다시 베이크했다. `build_assets.py`에도 같은 각도를 반영했다. 방·문·이동 경로·장비 예약 좌표는 유지한다. `turn_treatment_couches.py`는 기존 원본을 변환한 일회성 마이그레이션이며 새로 생성하는 경우에는 필요 없다.

환자의 몸통 뒤쪽은 매트리스 높이 약 1.08에, 머리 뒤쪽은 베개 높이 약 1.21에 맞췄다. 치료기와 같은 방향으로 누우며 선택 충돌체도 눕는 방향을 따른다. 누운 얼굴 앞면의 클릭이 몸통 영역을 빗나가는 경우를 발견해 얼굴의 선택 영역도 별도로 맞추었다. CT와 두 치료실에서 얼굴을 눌러 같은 환자가 선택되는지 검사한다. 치료 표시 빔은 헤드와 몸 사이의 짧은 구간만 표시한다.

실제 캐릭터 메시의 몸통·머리·발 범위를 침대 좌표로 변환해 지지면과 침대 길이, 치료 헤드 아래 간격을 검사한다. 두 치료실에서 얼굴까지의 카메라 시선이 실제 정적 장비 삼각형에 막히지 않는지도 별도로 검사한다. 이는 최종 스킨 리깅이나 모든 동작의 정밀 충돌 검사를 완료했다는 뜻은 아니다. 걷기→눕기의 자연스러운 전환과 세밀한 표정 연기는 후속 과제다.

## 전달 및 검증

결과 화면·영상과 최종 검사 수치는 [플레이 검토 페이지](play-feedback.html)와 [검증 기록](validation.md)에 정리한다. 정상 속도 영상은 실제 게임의 1배속 처리를 그대로 실행하며 입력만 자동화한다. 환자 직접 선택·목록 선택·접수·계획 지시와 대기·치료를 보여 준다. 6배속 영상은 기존 전체 운영 흐름을 확인하는 자동 시연이다. 영상 인코딩 프레임 수는 실기기 성능 수치가 아니다.

Linux Godot Compatibility와 Chromium WebGL을 기준으로 확인한다. 실제 Mac/iPhone Safari의 성능·발열·중단 후 저장 유지와 공개 Pages 접속은 별도 검증이 필요하다.
