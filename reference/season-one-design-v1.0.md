아래는 **첫 병원 운영부터 연구소·지역 확장·첫 해외 진출까지 실제로 구현할 수 있도록 작성한 상세 기획안 v1.0**입니다.

목표는 기능을 나열한 문서가 아니라, **첫 실행부터 첫 시즌 엔딩까지 플레이가 이어지는 게임의 설계도**입니다. 화면, 행동, 조건, 비용, 보상, 예외 처리를 함께 정했습니다.

기존에 합의한 **실제 3D·고정 카메라·A+C 아트·Android/iOS·병원 네트워크 성장**은 유지했습니다. 아래의 구체적인 수치와 새 규칙은 빈칸 없이 제작하기 위한 **구현용 기본안**이며, 실제 플레이 결과를 보고 조정합니다. 문서의 상세함과 실제 게임의 완성도는 별개이므로, 마지막에는 반드시 충족해야 할 검수 기준도 포함했습니다.

**1. 《햇살병원 방사선과》는 작은 병원을 세계적인 치료 네트워크로 성장시키는 모바일 경영 게임입니다.**

플레이어는 햇살병원의 새로운 운영 책임자입니다. 환자를 안내하고, 직원의 일을 배분하고, 병원의 부족한 부분에 투자합니다.

첫날에는 환자 한 명을 제대로 안내하는 것이 중요합니다. 병원이 성장하면 장비와 직원의 효율을 관리하게 되고, 이후에는 연구 방향과 새로운 지역에 대한 투자를 결정합니다.

병원을 키우는 이유는 이야기 속에서 발견됩니다. 기다리는 환자, 바쁜 직원, 먼 지역에서 찾아오는 사람들의 사연이 다음 기능을 여는 계기가 됩니다.

| 항목 | 제작 기준 |
|---|---|
| 게임명 | 햇살병원 방사선과 |
| 화면 표시명 | 햇살병원 |
| 장르 | 병원 경영·성장 시뮬레이션 |
| 플랫폼 | Android·iOS |
| 화면 방향 | 세로 |
| 공간 표현 | 실제 3D, 고정된 비스듬한 카메라 |
| 엔진 기준 | Godot 4.6.3 프로젝트를 출발점으로 사용 |
| 첫 시즌 범위 | 본원 1곳, 국내 분원 1곳, 해외 협력병원 1곳, 중앙 연구소 |
| 플레이 형태 | 로컬 싱글플레이 |
| 시간 진행 | 게임을 켜고 운영하는 동안 진행 |
| 인터넷 | 첫 시즌의 일반 플레이에는 필요 없음 |
| 첫 시즌 목표 시간 | 약 3~5시간을 초기 조정 목표로 설정 |
| 이후 플레이 | 엔딩 후에도 병원 운영과 남은 연구 진행 가능 |

출시 시점의 광고·결제 방식은 별도 결정합니다. **첫 시즌 제작과 검증은 광고나 결제 없이도 완결되는 구조**로 진행합니다.

**2. 플레이어가 반복해서 느껴야 하는 재미는 ‘돌봄·개선·성장’입니다.**

세 가지 경험을 게임의 중심에 둡니다.

| 경험 | 플레이어 행동 | 눈으로 확인하는 결과 |
|---|---|---|
| 돌봄 | 환자를 선택하고 필요한 과정을 안내 | 낯설어하던 환자가 익숙하게 병원을 방문 |
| 개선 | 대기 원인을 찾아 직원·장비·공간에 투자 | 대기열이 줄고 직원의 움직임이 정리됨 |
| 성장 | 증축·연구·분원 설립 | 작은 건물 옆에 별관이 생기고 지도에 새 병원이 등장 |

기본 운영 순환은 다음과 같습니다.

**환자 방문 → 접수 → 필요한 검사·계획 → 치료 → 오늘 일정 완료 → 수입·평판 → 직원·장비·증축·연구 투자**

장기 성장 순환은 다음과 같습니다.

**본원 안정화 → 운영 위임 → 연구소 설립 → 국내 분원 → 지역별 운영 개선 → 해외 협력병원 → 네트워크 완성**

돈을 얻는 순간만 보상으로 만들지 않습니다. 환자 대사, 직원의 여유, 공간 변화, 새로운 장비의 작동 모습도 보상으로 사용합니다.

**3. 첫 시즌에는 끝까지 완성할 범위를 명확히 제한합니다.**

| 반드시 구현 | 첫 시즌 이후로 미룸 |
|---|---|
| 환자 접수·이동·검사·계획·치료·귀가 | 자유로운 도시 전체 건설 |
| 장비 예약과 대기열 | 모든 벽·문·가구의 자유 배치 |
| 직원 채용·교육·자동 운영 | 온라인 협동·경쟁 |
| 본원 증축과 장비 개선 | 계정 기반 클라우드 저장 |
| 짧은 선택형 계획 퍼즐 | 사실적인 의료 시뮬레이션 |
| 연구소와 연구 9개 | 무한한 국가·지역 생성 |
| 국내 분원·해외 협력병원 | 다층 건물 전체를 자유롭게 오가는 운영 |
| 주요 스토리 8개 챕터 | 실시간 세계 경제 |
| 저장·복원·설정·엔딩 | 시즌 이벤트와 정기 라이브 서비스 |

첫 시즌의 시설은 **정해진 부지에 정해진 모듈을 설치하는 방식**입니다. 사용자는 무엇을 먼저 만들지 선택하고, 게임은 자연스럽게 연결된 공간을 제공합니다.

자유 건축은 장기 확장 기능으로 남깁니다.

**4. 게임의 시간은 한 번의 짧은 접속으로 하루 운영을 마칠 수 있게 설계합니다.**

기본값은 다음과 같습니다.

| 항목 | 기본값 |
|---|---:|
| 게임 내 영업시간 | 09:00~18:00 |
| 정상 속도에서 하루 시간 | 360초 |

18시가 되어도 환자를 갑자기 내보내지 않습니다. 화면에 **‘남은 진료를 마무리하고 있어요’**를 표시하고 계속 운영합니다. 이 연장 시간은 다음 날의 ‘정시 운영’ 평가에 반영합니다.

앱이 백그라운드로 이동하면 시간을 멈추고 저장합니다. 첫 시즌에는 접속하지 않은 동안 자동 수익이 쌓이는 기능을 넣지 않습니다.

**7. 환자를 선택하는 방법은 두 가지로 제공합니다.**

첫 번째는 3D 공간에서 환자를 직접 누르는 방법입니다. 두 번째는 환자 목록에서 이름을 누르는 방법입니다.

선택하면 다음 변화가 동시에 나타납니다.

- 환자 아래에 선택 표시.
- 이름표 강조.
- 하단에 환자 카드 표시.
- 가능한 행동 버튼 표시.
- 환자가 가려져 있으면 카메라가 소폭 이동하거나 가리는 벽이 흐려짐.

카메라 방향 자체는 회전시키지 않습니다.

환자 카드에는 다음 정보만 우선 표시합니다.

> 김영수 · 첫 방문  
> 계획 검토가 필요해요  
> 오늘 일정: 접수 ✓ → CT ✓ → 계획 → 치료  
> [계획 맡기기]

자세한 사연과 전체 치료 과정은 ‘자세히’에서 확인합니다.

환자 목록의 기본 정렬 순서는 다음과 같습니다.

1. 플레이어의 조작이 필요한 환자
2. 오래 기다린 환자
3. 이동·검사·치료 중인 환자
4. 오늘 일정을 마친 환자

사용자가 목록을 보고 있는 동안 항목이 계속 위치를 바꾸지 않도록, 정렬 갱신은 목록을 다시 열거나 ‘정렬’ 버튼을 눌렀을 때 적용합니다. 상태 글자는 실시간으로 바뀝니다.

**8. 환자 상태는 색상뿐 아니라 문구와 아이콘으로 구분합니다.**

| 상태 | 표시 문구 | 행동 |
|---|---|---|
| 입장 | 병원에 들어오는 중 | 선택 가능, 업무 버튼 없음 |
| 접수 대기 | 접수 필요 | 접수 |
| CT 대기 | CT 대기 · 앞에 1명 | 대기 상태 확인 |
| CT 이동 | CT실로 이동 중 | 이동 확인 |
| CT 진행 | CT 촬영 중 | 진행 표시 |
| 계획 준비 | 계획 필요 | 맡기기 또는 직접 계획 |
| 계획 대기 | 계획 검토 대기 | 대기 상태 확인 |
| 계획 진행 | 계획 검토 중 | 진행 표시 |
| 치료 대기 | 치료 대기 · 앞에 2명 | 대기 상태 확인 |
| 치료 이동 | 치료실로 이동 중 | 이동 확인 |
| 치료 진행 | 오늘 치료 진행 중 | 진행 표시 |
| 귀가 | 오늘 일정 완료 | 짧은 인사 |
| 퇴장 완료 | 오늘 진료 완료 | 당일 완료 목록으로 이동 |

조작이 필요한 상태는 따뜻한 노란색, 선택은 청록색, 정상 진행은 차분한 중간색을 사용합니다.

기본적인 대기 자체를 빨간 경고로 표현하지 않습니다. 장비 점검이나 처리되지 않은 오래된 업무처럼 실제 확인이 필요한 상황에만 경고색을 사용합니다.

**9. 환자는 한 번 방문하고 사라지는 사람과, 이야기를 가진 재방문 환자로 구성합니다.**

첫 시즌의 치료 과정은 게임 진행을 위해 축약합니다.

| 과정 | 방문 횟수 | 첫 방문 | 이후 방문 |
|---|---:|---|---|
| 기본 과정 | 3회 | 접수·CT·계획·치료 | 접수·치료 |
| 일반 과정 | 5회 | 접수·CT·계획·치료 | 접수·치료 |
| 확장 과정 | 7회 | 접수·CT·계획·치료 | 접수·치료 |

이 횟수는 실제 의료 과정을 설명하는 값이 아니라 게임용 구성입니다.

환자에게는 두 개의 진행도가 있습니다.

- **오늘 일정:** 오늘 방문에서 무엇을 해야 하는지.
- **전체 과정:** 총 방문 중 몇 회를 마쳤는지.

표시 예:

> 오늘 치료 완료  
> 전체 과정 2/3회 · 다음 방문은 내일

첫 방문 이후에는 CT와 계획을 매일 반복하지 않습니다. 별도의 스토리 사건이나 확장 콘텐츠가 있을 때 재검토를 추가할 수 있지만, 첫 시즌 기본 운영에서는 단순한 재방문 규칙을 사용합니다.

환자의 전체 과정이 끝나면 ‘과정 완료 기록’과 짧은 후일담을 남깁니다. 모든 환자에게 긴 대화를 강제로 보여주지는 않습니다.

**10. 예약은 기존 환자의 다음 방문을 먼저 확보합니다.**

하루가 시작되기 전 다음 순서로 예약을 만듭니다.

1. 기존 환자의 재방문 예약을 배정합니다.
2. 남은 자리에 신규 환자를 배정합니다.
3. 해당 환자의 이후 방문 자리도 확인합니다.
4. 자리가 없으면 신규 요청을 다음 가능한 날짜로 안내합니다.

재방문 환자가 신규 환자 때문에 매번 밀리는 구조는 피합니다.

기본 신규 요청 수는 병원별로 다음 식을 사용합니다.

> 하루 신규 요청 수 = 4 + 평판 20점마다 1명

실제 신규 예약 수는 빈자리와 이후 예약 가능 수를 넘지 않습니다.

첫날 튜토리얼은 예외로 정확히 네 명의 환자를 배정합니다.

환자 도착은 한꺼번에 화면 밖에서 나타나지 않고 시간표에 따라 진행합니다. 첫날에는 학습을 위해 도착 간격을 짧게 잡고, 이후에는 다음 패턴을 혼합합니다.

- 오전 집중 방문
- 오전·오후 분산 방문
- 재방문 중심의 비교적 안정된 날

예약된 환자 수와 아직 도착하지 않은 환자 수는 목록에서 확인할 수 있습니다.

**11. 장비는 이동 중 예약과 실제 사용 상태를 구분합니다.**

환자에게 장비를 배정하면 해당 장비는 **‘예약됨’** 상태가 됩니다. 환자가 도착해야 실제 작업 시간이 시작됩니다.

| 장비 상태 | 의미 |
|---|---|
| 사용 가능 | 새 환자 배정 가능 |
| 예약됨 | 환자가 이동 중 |
| 사용 중 | 검사·치료 진행 |
| 점검 대기 | 현재 환자 종료 후 점검 예정 |
| 점검 중 | 새 환자 배정 불가 |

대기열은 기본적으로 먼저 준비된 환자부터 처리합니다. 같은 시점이면 접수 순서를 사용합니다.

한 환자를 두 장비에 동시에 배정하거나, 한 장비로 두 환자를 동시에 보내면 안 됩니다.

첫 제작용 시간은 다음과 같습니다.

| 업무 | 기본 과정 | 일반 과정 | 확장 과정 |
|---|---:|---:|---:|
| CT | 12초 | 16초 | 20초 |
| 자동 계획 검토 | 18초 | 24초 | 30초 |
| 치료 | 40초 | 48초 | 56초 |
| 자동 접수 처리 | 3초 | 3초 | 3초 |

기존 프로토타입의 5초·5초·30초보다 길어진 값입니다. 정식 운영의 대기와 투자 판단을 확인하기 위한 새 기본안이며, 실제 이동시간을 포함해 다시 조정합니다.

**12. 환자가 기다리는 이유를 게임이 설명해야 합니다.**

대기 표시에는 단순히 ‘기다리는 중’만 쓰지 않습니다.

예:

- CT 장비를 사용 중이에요.
- 계획 담당자가 앞 환자를 검토하고 있어요.
- 치료실 두 곳이 모두 사용 중이에요.
- 장비 점검이 끝나면 안내해 드려요.
- 접수를 진행해 주세요.

선택 환자 카드에는 다음 세 가지를 제공합니다.

- 기다리는 장소
- 앞에 있는 환자 수
- 플레이어가 할 수 있는 행동 유무

대기시간은 **환자가 실제로 준비된 뒤 다음 업무를 시작할 때까지의 시간**으로 계산합니다. 이동시간은 대기시간에 포함하지 않습니다.

환자 만족도 기본값은 90점입니다.

> 당일 만족도 = 90 − 초과 대기 감점 + 편의시설 보너스  
> 최종 범위: 40~100점

초기 수치:

- 누적 대기 60초까지: 감점 없음
- 이후 10초마다: 2점 감소
- 대기실 개선: 최대 6점 보너스
- 당일 안내 사건 완료: 최대 4점 보너스

첫 시즌에서는 대기가 길다고 환자가 갑자기 사라지는 기능을 넣지 않습니다. 대신 만족도와 일일 평가에 반영합니다.

**13. 치료 성과는 연구와 직원 성장의 효과를 보여주는 게임 지표입니다.**

게임에는 **‘진료품질’**과 **‘과정 완료’**를 분리해서 표시합니다.

- 진료품질: 계획·장비·교육·연구를 통해 개선되는 게임 점수
- 과정 완료: 예정된 방문을 마쳤는지 여부

진료품질을 실제 완치 확률처럼 표시하지 않습니다.

초기 계산식은 다음과 같습니다.

> 진료품질 = 72 + 계획점수 × 0.1 + 장비 보너스 + 교육 보너스 + 연구 보너스  
> 최종 범위: 0~98점

| 요소 | 범위 |
|---|---:|
| 계획점수 | 0~100 |
| 장비 보너스 | 0 / 3 / 6 |
| 교육 보너스 | 0 / 3 / 6 |
| 공통 연구 보너스 | 0 / 2 / 4 |

환자의 과정 기록에는 방문별 진료품질 평균을 남깁니다. 병원 평가 화면에는 그날의 평균을 표시합니다.

환자의 회복 이야기와 후일담은 캐릭터 시나리오에 따라 진행합니다. 낮은 게임 점수 때문에 갑자기 사망하는 식의 처벌 시스템은 넣지 않습니다.

---

**14. 직접 계획 퍼즐은 선택형 콘텐츠로 넣습니다.**

초반에는 직원에게 맡기는 방법만 사용합니다. 첫 계획 연구를 마치면 직접 계획 기능을 엽니다.

퍼즐의 목적은 복잡한 의료 계산을 가르치는 것이 아니라, **목표 영역을 잘 포함하면서 피해야 하는 영역을 덜 건드리는 짧은 공간 퍼즐**을 제공하는 것입니다.

구성:

| 항목 | 규칙 |
|---|---|
| 판 | 5×5 추상 격자 |
| 목표 영역 | 연결된 칸 4개 |
| 주의 영역 | 목표와 겹치지 않는 칸 4개 |
| 선택 후보 | 서로 다른 범위 모양 5개 |
| 선택 수 | 후보 중 2개 |
| 제한시간 | 없음 |
| 권장 소요시간 | 15~30초 |
| 초반 문제 수 | 검수한 고정 문제 10개 |
| 취소 | 불이익 없이 이전 상태로 복귀 |

초기 점수 계산:

> 50 + 목표 포함 비율 × 50  
> − 일반 영역에 영향을 준 칸 수 × 2  
> − 주의 영역에 영향을 준 칸 수 × 8

최종 점수는 0~100점으로 제한합니다.

모든 문제에는 85점 이상을 얻을 수 있는 조합을 최소 한 개 확보합니다. 생성형 무작위 문제보다 검수한 고정 문제부터 사용합니다.

퍼즐을 열면 모든 병원의 시간이 일시정지됩니다. 완료 후 의료진의 짧은 검토 동작을 거쳐 다음 단계로 진행합니다.

직접 계획은 선택 사항입니다. 이를 반복하지 않아도 자동 계획과 연구로 시즌을 완료할 수 있어야 합니다.

**15. 직원은 역할·숙련도·자동 운영 범위로 구분합니다.**

| 역할 | 주요 업무 | 자동 운영 효과 |
|---|---|---|
| 안내 직원 | 접수, 대기 안내 | 접수 대기 환자 자동 처리 |
| 방사선사 | CT·치료 준비와 장비 업무 | 배정된 장비 운영 |
| 계획 담당자 | 치료계획 검토 | 준비된 환자의 계획 자동 시작 |
| 운영 책임 직원 | 여러 업무의 연결과 관리 | 다른 병원 방문 중에도 운영 유지 |
| 연구 인력 | 연구 프로젝트 | 연구 진행과 연구 성과 생산 |

박 원장·민지 같은 주요 인물은 스토리 인물로 유지합니다. 일반 채용 직원은 여러 외형과 이름을 사용하는 인물로 구성합니다.

첫 시즌에는 복잡한 피로·휴가·퇴사 시스템을 넣지 않습니다. 직원에게 무작위로 불리한 성격을 붙여 운영을 방해하는 기능도 제외합니다.

직원 성장의 기본 구조:

| 단계 | 효과 |
|---|---|
| 입문 | 기본 업무 수행 |
| 숙련 | 관련 업무 시간 10% 감소 |
| 전문 | 관련 업무 시간 15% 감소, 교육 보너스 제공 |

교육은 돈을 지불하고 일정 운영일을 보내는 방식입니다. 교육 기간 중에도 기존 업무는 수행하며, 효과는 다음 날 시작 시 적용합니다.

**16. 자동 운영은 일을 없애는 기능이 아니라 플레이어의 관심 범위를 넓히는 기능입니다.**

해금 순서는 다음과 같습니다.

1. 첫 챕터: 접수와 계획을 직접 지시
2. 직원 챕터: 접수 자동화
3. 운영 교육 완료: 계획 자동화
4. 분원 설립 전: 병원 운영 위임

자동 접수는 환자가 접수 대기 상태가 된 뒤 3초 후 실행합니다. 자동 계획도 필요한 상태가 된 뒤 직원과 장비 조건을 확인해 실행합니다.

플레이어가 먼저 행동하면 자동 행동은 취소됩니다. 같은 업무를 두 번 등록하면 안 됩니다.

다른 병원으로 이동할 때 현재 병원의 자동 운영이 꺼져 있으면 다음 안내를 보여줍니다.

> 병원 운영을 직원에게 맡기고 이동할까요?  
> [맡기고 이동] [돌아가기]

첫 분원 설립은 운영 위임 기능을 확보한 뒤에만 가능합니다.

자동 운영 이후의 플레이는 다음에 집중합니다.

- 어떤 병원에 투자할지
- 어떤 연구를 진행할지
- 어떤 장비를 개선할지
- 어떤 직원의 교육을 우선할지
- 지역 목표를 어떻게 달성할지

**18. 건설은 즉시 모델이 바뀌되, 짧은 완공 연출로 성장을 보여줍니다.**

첫 시즌에는 몇 시간씩 기다리는 건설 타이머를 넣지 않습니다.

건설 흐름:

1. 외부에서 부지를 선택
2. 건물 이름·효과·비용 확인
3. 구매 확인
4. 비용 차감
5. 3~5초의 완공 연출
6. 외관 모델 변경
7. 내부 공간과 장비 슬롯 추가
8. 직원 배치
9. 새 공간으로 카메라 안내
10. 저장

연출 중 환자 진행을 일시정지합니다.

증축은 진행 중인 환자의 치료를 취소하지 않습니다. 기존 장비와 경로는 유지하고 새 장비만 추가합니다.

새 병원 설립은 계약과 준비 연출을 보여주고, **다음 운영일부터 환자를 받습니다.** 설립 당일에 운영비만 먼저 부과하지 않습니다.

**20. 자금이 부족해도 기본 운영을 다시 시도할 수 있어야 합니다.**

하루 수입과 보유 자금으로 운영비를 모두 지불하지 못하면:

- 자금은 0 아래로 내려가지 않습니다.
- 부족분을 미납 운영비로 기록합니다.
- 기본 진료는 계속할 수 있습니다.
- 새로운 병원·선택 시설 구매는 미납 정리 전까지 제한합니다.
- 이후 흑자의 25%를 미납 상환에 사용합니다.
- 이자는 붙이지 않습니다.

기본 장비를 갑자기 모두 멈추거나 저장을 초기화하게 만들지 않습니다.

화면 문구:

> 운영비 일부가 남아 있어요.  
> 진료는 계속할 수 있으며, 앞으로 발생하는 흑자의 일부로 정리됩니다.

이 규칙은 실패를 무시하기 위한 것이 아니라, 잘못된 투자 한 번으로 진행이 영구적으로 막히는 것을 방지하기 위한 것입니다.

> **민지:** 저쪽 공간을 연결하면 치료실을 하나 더 만들 수 있을 것 같아요.

증축 완료 후 두 치료실이 실제 가동되는 순간:

> **민지:** 두 분을 각각 안내할 수 있게 됐어요. 복도 분위기도 달라졌네요.  
> **박 원장:** 늘어난 공간만큼 잘 준비해서 운영해 보세.

챕터 3에서는 시설이 늘어난 뒤 민지의 업무가 겹치는 상황을 보여줍니다.

> **민지:** 접수대에 다녀오는 동안 다음 치료 준비가 쌓였네요.  
> **박 원장:** 공간만 늘린다고 일이 저절로 나뉘는 건 아니지.

안내 직원 채용 후:

> **새 직원:** 접수부터 맡아볼게요. 모르는 건 바로 여쭤보겠습니다.  
> **민지:** 좋아요. 제가 자주 받는 질문도 같이 정리해 드릴게요.

자동 운영으로 하루를 마치면:

> **민지:** 오늘은 설명을 서두르지 않아도 됐어요. 환자분 말씀도 끝까지 들을 수 있었고요.

챕터 4에서는 윤서진이 운영 기록을 확인합니다.

> **윤서진:** 같은 장비를 쓰는데 날마다 걸리는 시간이 조금씩 달라요. 기록을 모으면 개선할 부분을 찾을 수 있겠어요.  
> **박 원장:** 현장에서 느끼던 문제를 제대로 살펴볼 곳이 필요하겠군.

첫 연구 완료:

> **윤서진:** 첫 결과가 나왔어요. 이제 현장에서 적용해 보고 다시 확인하면 됩니다.

같은 환자의 이야기를 처음부터 반복하지 않습니다. 완료한 장면은 기록 화면에서 다시 볼 수 있습니다.

**33. 아트는 승인한 A+C 방향을 제작 가능한 규칙으로 고정합니다.**

공간의 기본 조합:

- 크림색 벽과 장비 외장
- 청록·민트 계열의 포인트
- 자연스러운 밝은 목재
- 코랄색 소파와 작은 색상 변화
- 녹색 식물과 노란 꽃
- 부드럽고 따뜻한 조명

피해야 할 표현:

- 형태를 알아보기 어려운 각진 블록 인물
- 바닥과 장비가 전부 하얗게 날아가는 조명
- 모든 재질이 같은 플라스틱처럼 보이는 표면
- 큰 UI 카드가 병원 대부분을 가리는 화면
- 실제 모델 대신 전체 콘셉트 이미지를 배경으로 사용
- 환자와 직원의 크기가 가구·장비와 맞지 않는 배치

캐릭터 기준:

- 약 2.5~3등신의 작은 비율
- 얼굴·머리·몸통·손·신발이 구분되는 형태
- 눈과 입의 기본 표정 변화
- 걷기·대기·인사·앉기·눕기·업무 동작
- 같은 골격을 활용하되 머리와 옷으로 개성 구분

장비 기준:

- CT는 원형 구멍과 그 안으로 들어가는 환자 테이블이 분명해야 함
- 방사선치료기는 치료 헤드·회전 구조·환자 테이블이 구분되어야 함
- 계획실은 작업대와 모니터의 역할이 보이도록 구성
- 장비 주변에 환자와 직원이 이동할 여유 공간 확보

외관은 본원·분원·연구소가 같은 브랜드로 보이되 지붕, 창문, 조경, 주변 지형에서 차이를 줍니다.

**36. 저장은 여러 병원과 스토리 진행을 함께 보존해야 합니다.**

|---|---|

| 직원 | 역할, 배정, 숙련도, 교육 |
| 연구 | 연구소 단계, 점수, 진행 프로젝트, 완료 연구 |

저장 시점:

- 주요 구매 확정 후
- 치료 수입 처리 후
- 챕터 보상 처리 후
- 연구 시작·완료 후
- 병원 전환 전
- 하루 정산 후
- 앱 백그라운드 이동
- 운영 중 일정 간격

파일은 임시 파일에 기록한 뒤 교체하는 방식으로 저장합니다. 직전 정상 저장 한 개를 추가로 보관합니다.

복원 후에는 시간을 일시정지하고 다음 문구를 보여줍니다.

> 이어서 운영할 준비가 됐어요.  
> 재생을 누르면 환자와 직원이 다시 움직입니다.

저장이 손상되면 기존 파일을 즉시 덮어쓰지 않습니다. 정상 보조 저장이 있으면 복구 가능 여부를 안내합니다.

기존 `hospital_v2.json`이 발견되면 실제 내용을 확인해 이전 규칙을 작성합니다. 새 기능을 추가했다는 이유로 사용자 진행을 조용히 초기화하면 안 됩니다.

| 도착 예정 환자가 남아 있음 | 조기 마감 불가, 남은 예약 수 표시 |
| 돈 부족 | 버튼에 부족 금액 표시, 결제하지 않음 |
| 해금 조건 부족 | 필요한 조건을 구체적으로 표시 |
| 경로를 찾지 못함 | 환자를 삭제하지 않고 안전한 대기 위치로 보정·진단 기록 |
| 긴 이름·큰 금액 | UI가 화면 밖으로 넘치지 않도록 처리 |
| 저장 실패 | 플레이를 유지하며 명확한 상태 표시 |

다른 창이 떠 있는 상태에서 뒤쪽 버튼을 잘못 누르지 않도록 모달 입력을 차단합니다. 휴대폰 뒤로 가기는 가장 위의 창부터 닫습니다.

경제 수치, 연구 효과, 챕터 조건, 대사는 코드 곳곳에 흩어놓지 않고 데이터로 관리합니다.

새 채팅의 현재 구현이 기능 검증용 모형이라면, 기존 운영 코드는 보존하면서 다음을 한 묶음으로 진행합니다.

2. **환자 목록을 간결하게 만들고, 조작이 필요한 환자를 분명하게 표시합니다.**
3. **첫 환자의 접수부터 오늘 일정 완료까지 챕터 1 대사를 연결합니다.**

5. **실제 휴대폰 크기의 화면과 짧은 플레이 영상으로 확인합니다.**
6. **소스와 결과물을 독립적으로 접근 가능한 위치에 보관하고, 실제 보관 성공을 확인합니다.**
